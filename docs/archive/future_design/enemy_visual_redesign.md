# 敌人视觉系统重设计：词缀特效与纹理

## 1. 移除 Elite / Boss 词条重构方案

目前，游戏中将 `elite` 和 `boss` 既作为 `type` 字段，又作为 `affixes`（词缀）数组中的元素。这种设计混淆了“敌人等级”和“词缀能力”的概念。为了清晰架构，我们需要将两者完全解耦。

在重构步骤上，首先需要从词缀池中移除相关的定义。在 `src/systems.js` 的 `renderAffixButtons` 方法中，应当从 `affixes` 数组中移除 `{ id: 'elite', name: '精英', icon: '💀' }` 这一项。同时，确保 `src/spawn_system.js` 中的 `spawn_generateAffixes` 方法不再生成 `elite` 或 `boss` 词缀。

其次，生成逻辑需要进行相应的调整。在 `src/spawn_system.js` 中，当生成带有词缀的敌人时，应直接设置 `e.type = 'elite'`，而不是向 `e.affixes` 中添加 `'elite'` 字符串。在 `Enemy` 构造函数（位于 `src/entities.js`）中，也需要移除 `if (this.affixes.includes('elite')) this.type = 'elite';` 这种隐式的类型转换逻辑。

最后，视觉判断逻辑也需要解耦。在 `src/entities.js` 的 `draw` 方法中，必须移除依据 `this.affixes.includes('elite')` 来绘制 `💀` emoji 的相关代码。`elite`（深紫底色、金色边框）和 `boss`（深红底色、红色边框）的视觉差异将完全由 `this.type` 字段决定，这部分现有的绘制代码可以保持不变。通过这些重构，`type` 将专职控制敌人的基础属性面板（如血量倍率、底色、边框粗细），而 `affixes` 则专职控制敌人的特殊机制（如护盾、极速等），使得两者成为正交的概念，互不干扰。

## 2. 词缀视觉特效系统设计

为了替换现有的 emoji 角标，我们将为 7 种词缀设计专属的 Canvas 2D 视觉特效。这些特效将绘制在全新的 **Layer 8（词缀光环层）**，该层位于外部特效（Layer 6）和扫描反馈（Layer 7）之间，以确保特效常驻可见且不会被其他元素遮挡。所有的动态效果都将基于 `Date.now()` 进行低频脉冲计算（频率不超过 1Hz），从而保证对性能的友好。

| 词缀类型 | 视觉概念 | 颜色系 | 特效设计 | 动态效果 |
| :--- | :--- | :--- | :--- | :--- |
| **Shield（护盾）** | 坚固的能量屏障 | 浅蓝色（`#93c5fd`） | 在敌人容器外围绘制一个略大的六边形（或带有切角的矩形）线框。线框使用虚线表示能量流转，并带有轻微的发光效果。 | 线框的透明度随时间进行缓慢的呼吸脉冲（透明度在 0.6 至 0.9 之间变化）。 |
| **Regen（再生）** | 生生不息的自然生命力 | 绿色（`#4ade80`） | 在敌人容器底部的四个角落，向外延伸出类似藤蔓或叶片的几何折线。 | 折线的末端会周期性地闪烁微光，模拟生命能量的注入过程。 |
| **Haste（极速）** | 残影与速度感 | 黄色/白色（`#facc15` / `#ffffff`） | 在敌人容器的左右两侧，绘制两道平行的倾斜速度线（Speed Lines）。 | 速度线的位置和透明度随时间产生快速但微小的水平位移，营造出随时准备冲刺的残影感。 |
| **Clone（增殖）** | 细胞分裂、不稳定状态 | 紫色（`#c084fc`） | 在敌人容器内部，血条之上，绘制几个半透明的圆形斑点，模拟正在分裂的细胞核。 | 这些斑点会缓慢地收缩和膨胀，并且位置会有极其轻微的游离。 |
| **Devour（吞噬）** | 侵蚀、深渊 | 暗红/黑色（`#991b1b` / `#000000`） | 在敌人容器的底部边缘，绘制锯齿状的暗红色阴影，仿佛底部的空间正在被吞噬。 | 锯齿的顶点高度随时间进行不规则的蠕动变化。 |
| **Healer（治愈）** | 向外辐射的治愈光波 | 粉色/金色（`#f472b6` / `#fde047`） | 在敌人容器的顶部中心，绘制一个向外散发的十字星光芒图案。 | 十字星的四角会缓慢旋转，并伴随透明度的呼吸效果。 |
| **Jump（跳跃）** | 蓄力、弹簧 | 青色（`#2dd4bf`） | 在敌人容器的下方，绘制两条向外弯曲的弧线，形似被压缩的弹簧或气流。 | 弧线的曲率随时间周期性变化，模拟蓄力待发的状态。 |

## 3. 多词缀叠加规则设计

当一个敌人同时拥有多个词缀时，为了避免视觉上的混乱，需要采用明确的叠加规则。首先是空间隔离原则，不同的特效将占据不同的绘制区域。例如，`Shield` 占据外围整体轮廓，`Haste` 占据左右两侧，`Regen` 占据底部四角，`Devour` 占据底部边缘，`Jump` 占据正下方，`Healer` 占据顶部中心，而 `Clone` 则占据内部血条区域。通过合理分配绘制区域，可以确保多数词缀能够共存而不会发生严重的重叠。

其次是优先级与透明度衰减规则。如果某些特效（如 `Shield` 的外框与 `Haste` 的侧边线）在空间上不可避免地产生交集，则应当采用叠加混合模式（`globalCompositeOperation = 'lighter'`）来处理。此外，当敌人身上的词缀数量较多时，整体特效的基础透明度应当适当降低。例如，当词缀数量超过 3 个时，可以将所有特效的透明度乘以 0.8，以防止画面出现过曝现象。

## 4. 敌人底层纹理设计方案

为了进一步提升敌人的暗黑炼金质感，我们将为其添加静态预计算的底层纹理。在实现方式上，可以在 `Enemy` 类初始化时，利用 `this.visualSeed` 生成一个离屏 Canvas（OffscreenCanvas），并在其中绘制噪点、金属拉丝或矿石纹理。在主循环的 `draw` 方法中，直接将该离屏 Canvas 作为图像绘制到 Layer 2（血条）和 Layer 3（内部覆盖层）之间。

纹理的风格将基于 `visualSeed` 来决定。例如，当 `seed < 0.3` 时，生成垂直的金属拉丝纹理；当 `0.3 <= seed < 0.6` 时，生成粗糙的矿石斑点纹理；当 `seed >= 0.6` 时，则生成微弱的能量流线纹理。颜色方面，应当使用极低透明度的暗色调（如 `rgba(0, 0, 0, 0.15)` 或 `rgba(255, 255, 255, 0.05)`），以确保不会影响血条颜色和词缀特效的辨识度。由于这种方法使用的是预计算的静态图像，每帧只需执行一次 `drawImage` 操作，因此性能开销极低，具有显著的性能优势。

## 6. 性能影响评估

在性能影响方面，底层纹理使用了离屏 Canvas 进行预计算，每帧仅增加一次 `drawImage` 调用，这种 O(1) 复杂度的操作对性能的影响可以忽略不计。对于词缀特效，所有的绘制均使用了基础的 Canvas 2D 路径绘制 API（如 `beginPath`, `moveTo`, `lineTo`, `arc`, `stroke`, `fill` 等），并没有引入复杂的粒子系统。动态效果完全通过简单的数学函数（如 `Math.sin(Date.now() / 1000)`）计算得出。

单帧增加的绘制调用次数与敌人身上的词缀数量成正比（通常为 1 到 3 个），这在手机端也能稳定保持 60FPS 的帧率。作为进一步的优化建议，对于发光效果（`shadowBlur`），在低端设备上可以考虑通过全局配置开关，将其降级为半透明的描边（`strokeStyle`），以此来节省 GPU 资源，确保游戏的流畅运行。
