# 智能掉落权重计算框架设计

本规划针对“发射器符文词条系统”的智能掉落机制，设计了从玩家行为分析到掉落结果生成的完整链路。核心思想是建立“玩家套路识别 → 克制关系映射 → 符文关联”的三层逻辑，确保掉落的符文既符合随机性，又能动态响应玩家的流派选择。

## 第一层：玩家套路成分识别 (Player Build Analysis)

**目标**：量化玩家当前正在使用的各种流派（套路）的占比。

**实现思路**：
利用游戏现有的伤害统计系统（`combat_system.js` 中的 `combat_recordDamage` 和 `currentShotDamageByAttr`）作为主要数据来源。

1.  **数据采集**：在每回合结束或敌人死亡时，汇总最近 N 个回合的伤害数据，按属性类型（如 `pyro`, `cryo`, `lightning`, `bounce`, `pierce` 等）进行分类。
2.  **权重计算**：将各类伤害值转化为百分比。例如，若总伤害为 1000，其中火焰伤害 400，弹射伤害 200，则套路成分识别为：`40% 火焰套路 (Pyro)`, `20% 弹射套路 (Bounce)`。
3.  **平滑处理**：为了避免单回合的极端数据导致掉落突变，可引入移动平均算法（Moving Average），结合历史权重与当前回合权重。

## 第二层：克制关系映射 (Counter Mapping)

**目标**：根据识别出的玩家套路成分，推导出需要生成哪些“克制标签”，并计算其权重。

**实现思路**：
建立一个静态的克制关系字典（Counter Dictionary），定义每种玩家套路需要哪些特定标签的敌人来应对，或者哪些标签的敌人最容易被该套路克制。

1.  **克制关系定义**：
    *   *示例 1*：如果玩家是 `pyro` (火焰) 套路，它可能克制带有 `shield` (护盾) 或 `cryo_resist` (冰抗) 标签的敌人。
    *   *示例 2*：如果玩家是 `bounce` (弹射) 套路，它可能非常依赖密集的敌人阵型，因此对应 `clone` (增殖) 或 `swarm` 标签。
2.  **权重转换**：将第一层得到的套路百分比，通过字典映射为敌人标签的权重。
    *   如果 `pyro` 占比 40%，且字典定义 `pyro -> shield (权重 1.0)`, `pyro -> regen (权重 0.5)`。
    *   则生成标签权重池：`shield` 获得 40% 的权重注入，`regen` 获得 20% 的权重注入。
3.  **复合标签处理**：如果多个套路都指向同一个敌人标签，则将其权重叠加。最终归一化得到一个“目标克制标签权重池”。

## 第三层：符文关联与掉落 (Rune Association & Drop)

**目标**：将第二层生成的“目标克制标签权重池”与具体的符文进行关联，最终决定掉落哪个符文。

**实现思路**：
在符文数据库中，为每个符文定义其“亲和标签”（Affinity Tags）。

1.  **符文亲和度定义**：
    *   *符文 A (烈焰符文)*：亲和标签为 `shield`, `regen`。
    *   *符文 B (穿透符文)*：亲和标签为 `shield`, `armor`。
2.  **匹配与抽取**：
    *   当需要生成掉落时，遍历所有可掉落的符文。
    *   计算每个符文的最终掉落权重：基础掉落权重 + (该符文亲和标签在第二层权重池中的值 * 智能掉落乘数)。
    *   例如，如果第二层算出 `shield` 的权重极高，那么所有亲和 `shield` 的符文（如烈焰符文、穿透符文）的掉落概率都会显著提升。
3.  **结果输出**：根据最终计算出的各个符文的综合权重，使用加权随机算法（Weighted Random Choice）抽取最终掉落的符文。

## 总结

此三层框架将玩家的动态战斗数据（伤害占比）转化为抽象的逻辑需求（克制标签），再将逻辑需求具象化为实际的奖励（符文）。这种解耦设计不仅保证了掉落系统的智能性，也极大地提高了后续添加新套路、新敌人标签或新符文时的可扩展性。
