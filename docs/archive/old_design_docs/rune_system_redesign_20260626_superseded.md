# 符文系统重构设计方案 (v2.0)

## 1. 核心设计目标

为了提升 Roguelike 游戏局内的成长深度与策略性，符文系统将从局外成长（Meta Progression）全面转移为**局内核心机制**。本次重构围绕以下核心理念展开：
1.  **动态掉落与自动拾取**：符文的获取应与玩家的战斗表现、回合进度及当前构建（Build）状态紧密相关。
2.  **双重增益机制**：符文不仅用于在 3x3 网格中拼凑「词条效果」，其本身也应提供基础的「属性层数」加成。
3.  **合成与重铸**：解决多余符文的冗余问题，提供同系合成（提升属性层数）与跨系重铸（获取新符文）的深度玩法。

---

## 2. 动态掉落与自动拾取系统

### 2.1 自动拾取机制
*   **生成与表现**：敌人死亡时，根据掉落率判定是否生成 `RuneLoot` 实体。该实体将在战场上悬浮发光。
*   **拾取逻辑**：在战斗阶段结束（`phase_combat_update` 检测到敌人清空且弹药耗尽）或回合结算（`phase_finalizeRound`）时，系统自动遍历场上所有的 `RuneLoot`，触发飞向玩家（或 UI 背包位置）的动画，并将其加入 `runeInventory`。

### 2.2 动态掉落率公式设计
为了保证前期稀缺、后期丰富的游戏节奏，同时避免满屏掉落，掉落率需综合考虑**回合数**、**当前敌人数量**以及**玩家当前的符文获取情况**。

**基础掉落率计算公式**：
```javascript
BaseDropRate = Math.min(0.05 + (Round / 10) * 0.05, 0.40)
```
*   *说明*：随回合数线性增长。第 1 回合基础掉落率为 5%，每 10 回合增加 5%，上限 40%。

**敌人数量修正系数**：
```javascript
EnemyModifier = Math.max(0.3, 1.0 / Math.sqrt(SpawnedEnemiesInRound))
```
*   *说明*：当单回合生成的敌人数量极多时（例如 20 个），单个敌人的掉落率应适当降低，以保证单回合期望掉落的总符文数在一个合理区间（如 1~3 个），避免背包瞬间爆满。

**背包与网格占用率衰减（防溢出机制）**：
```javascript
Occupancy = (runeInventory.length + runesInGrid) / MAX_CAPACITY
OccupancyPenalty = Math.max(0.2, 1.0 - Occupancy)
```
*   *说明*：当玩家囤积了大量未使用的符文时，掉落率会受到最高 80% 的惩罚衰减，鼓励玩家积极进行合成或重铸。

**最终单体敌人掉落率**：
```javascript
FinalDropRate = BaseDropRate * EnemyModifier * OccupancyPenalty
```

## 3. 符文双重增益机制

当前游戏中的弹药（Ammo）配方包含基础属性层数（如 `pyro: 1`, `bounce: 2`）。重构后的符文将直接对这些层数提供加成。

### 3.1 基础属性加成（单体增益）
每个符文除了拥有其所属的元素类型（Element）和用于激活词条的 ID 外，还将具备**等级（Level）**。
*   **等级效果**：符文的等级直接对应其提供的「属性层数」加成。
*   **应用方式**：只要符文被放置在 3x3 网格中，无论是否激活了词条，都会为玩家发射的所有弹药提供对应的属性层数加成。
*   *举例*：一个 `Level 2` 的「烈焰符文」（pyro），放置在网格中后，会使玩家所有子弹的 `pyro` 属性层数 +2。

### 3.2 词条效果加成（组合增益）
*   保持现有的 `RUNEWORD_DB` 机制。当网格中的符文排列满足特定形状（如直线、对角线）时，激活额外的词条效果（如「烈焰之语」）。
*   **独立性**：词条效果的激活与符文等级无关，只看符文 ID 与排列形状。

## 4. 符文合成与重铸系统

为了处理 `runeInventory` 中多余的符文，并在游戏后期提供资源转化途径，新增合成与重铸功能。

### 4.1 符文合成（提升等级）
*   **规则**：**三个同等级、同 ID** 的符文，可以合成为一个**高一等级**的同名符文。
    *   *公式*：`Rune A (Lv X) * 3  =>  Rune A (Lv X+1)`
*   **收益**：合成后的符文，其提供的基础属性层数加成提升（通常与等级等同，即 Lv2 提供 2 层，Lv3 提供 3 层）。
*   **限制**：合成**不改变**符文的 ID，因此不会影响其在 `RUNEWORD_DB` 中的词条拼凑判定。这保证了玩家在提升基础属性的同时，不会破坏已有的词条组合。

### 4.2 符文重铸（获取新符文）
*   **规则**：玩家可以放入**任意三个**不需要的符文进行重铸，产出一个全新的随机符文。
*   **等级继承**：重铸产出的新符文等级，由参与重铸的三个符文的等级决定。
    *   *公式*：`NewLevel = Math.max(1, Math.floor((Lv_A + Lv_B + Lv_C) / 3))`
    *   *说明*：取平均值并向下取整。这意味着使用高等级符文作为「垫子」可以重铸出高等级的新符文。
*   **智能掉落介入**：重铸产出的符文种类，应调用现有的 `loot_calcRuneDrop()` 智能掉落算法。该算法会根据玩家近期的伤害构成（如火焰伤害占比高），提高相应属性（如 pyro 关联符文）的出现概率。

## 5. 架构与代码修改指引

1.  **数据结构扩展**：
    *   修改 `rune_config.js` 中的 `RUNE_DB`，为每个符文增加基础属性映射定义（如 `baseStat: 'pyro'`）。
    *   修改背包与网格的数据结构，从存储简单的 `runeId` 字符串，改为存储对象 `{ id: 'rune_pyro_1', level: 1 }`。
2.  **掉落与拾取实现**：
    *   在 `combat_system.js` 中实现 `FinalDropRate` 的计算逻辑。
    *   在 `game_phase.js` 的回合结束逻辑中，遍历并清空 `runeLootItems`，将对象推入 `runeInventory`。
3.  **UI 交互开发**：
    *   在符文发射器（Rune Launcher）面板增加「合成」与「重铸」操作区。
    *   支持拖拽或点击选中三个符文进行操作。
4.  **属性应用逻辑**：
    *   在 `ui_system.js` 的 `ui_updateRuneGrid()` 中，除了调用 `parseRuneGrid` 获取词条加成外，还需遍历网格，累加所有单体符文的基础属性层数（根据其 Level）。
    *   将累加后的总基础属性，与词条属性合并，最终作用于 `combat_fireNextShot()` 中的弹药配方。
