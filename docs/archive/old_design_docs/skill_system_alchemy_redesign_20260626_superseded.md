# 技能体系遗物化与药剂炼成重设计方案

> 状态：首版已落地到代码（2026-06-26）。`relic_sage_apothecary`、`POTION_SPELL_DB`、炼金台药剂 Tab、药剂战斗槽与本局存档字段已实现；常规技能遗物化迁移仍按本文后续规划推进。
> 目标：技能跟随遗物解锁；常规技能消耗 SP 且有冷却；特殊遗物开启“药剂炼成”，通过融合符文生成有限次数法术，药剂法术不消耗 SP、无冷却，只消耗装药量。

## 0.1 2026-06-26 首版实现入口

- 配置：`src/config.js` 新增 `CONFIG.gameplay.potionAlchemyFailRefundRatio = 0.35`、`relic_sage_apothecary` 与 `POTION_SPELL_DB`。
- 状态：`src/core.js` / `src/game_system.js` 新增 `potionAlchemyUnlocked`、`preparedPotionSpell`、`knownPotionSpellIds`、`potionRecipeHistory`，并纳入本局存档。
- 解锁：`src/ui/shop.js` 在拾取 `unlock_potion_alchemy` 遗物时开启药剂炼成。
- UI：`index.html` 与 `src/ui/rune_launcher.js` 将符文发射器可见文案升级为“炼金台”，新增药剂 Tab、配方预览、覆盖确认、失败返还。
- 战斗：`src/systems.js` 在技能栏渲染药剂槽；`src/combat_system.js` 提供 `combat_activatePotionSpell()` / `combat_applyPotionSpell()`，药剂释放不消耗 SP，只扣装药量。

## 1. 核心结论

新技能体系分成两条清晰线路：

| 线路 | 来源 | 消耗 | 冷却 | UI 重点 |
|---|---|---|---|---|
| 遗物技能 | 获得对应遗物后解锁 | SP | 有冷却 | SP 消耗、冷却遮罩 |
| 药剂法术 | 获得特殊遗物后，在炼金台融合符文生成 | 使用次数 | 无冷却 | 装药量、药瓶遮罩 |

符文不再直接解锁常规技能。符文的技能相关职责集中到“药剂炼成”：玩家把多个符文投入炼金台，若配方成立则生成对应药剂法术；若配方不成立，符文照常消耗，只返还一部分局内货币。

### 1.1 设计支柱

- **遗物决定长期能力**：看到一个技能，就应该能追溯到一个具体遗物，而不是临时符文网格状态。
- **SP 决定强技能节奏**：SP 是常规技能的释放资源，冷却是常规技能的时间阀门。
- **符文决定药剂尝试**：多余符文不再只是库存，而是可以变成一次性法术资源。
- **药剂只有一瓶在装**：贤者药匣初版只允许同时装填 1 种药剂法术，调制新法术需要弃置旧法术。
- **失败有成本但不毁局**：失败消耗符文，但返还局内货币，让错误尝试不会完全变成空洞惩罚。

## 2. 遗物技能

### 2.1 解锁规则

所有常规主动技能都应由遗物解锁。获得遗物即把对应技能加入技能池，技能池中的技能可装备进战斗技能栏。

建议字段：

```js
{
    id: 'skill_gravity_well',
    source: 'relic',
    unlockRelic: 'relic_gravity_core',
    name: '引力坍缩',
    icon: '🕳️',
    spCost: 2,
    cooldownSec: 18,
    desc: '将所有敌人向上拉离防线 2 行，并造成回合数 × 3 伤害。',
    params: { pushRows: 2, roundMult: 3 }
}
```

### 2.2 战斗规则

- 释放常规遗物技能时检查：当前阶段、SP、冷却、技能是否已装备。
- 释放成功后扣除 SP，并写入 `skillCooldowns[skillId] = cooldownSec`。
- 冷却在战斗阶段按时间递减，离开战斗阶段可选择清零，初版建议清零，避免跨回合记忆成本。
- 若技能效果因无目标、无弹药等原因失败，返还 SP 且不进入冷却。

### 2.3 现有技能迁移

原 `base` / `runeword` / `shop` 技能应逐步迁移为遗物技能：

- 原 `base` 技能：转为新手遗物或开局固定遗物解锁。
- 原 `runeword` 技能：拆成对应主题遗物，如冰牢、雷神、熔毁、剑刃、聚变等。
- 原 `shop` 技能：商店不直接卖技能，改为卖“技能遗物”或含技能的临时遗物。
- 原 `unlockRuneword` 字段只保留为旧存档兼容，不再作为新解锁路径。

## 3. 特殊遗物：贤者药匣

“炼金药剂”建议改名为：**贤者药匣**。

理由：它不是一瓶一次性药剂，而是一个能装填、调制、封存多种法术药剂的遗物。“药匣”表达可多次装药，“贤者”贴合炼金母题，也比“炼金药剂”更像遗物名。

### 3.1 遗物效果

获得 `贤者药匣` 后：

- 解锁药剂技能槽：一个特殊主动槽，默认显示当前装填的药剂法术。
- 药剂技能无 SP 消耗、无冷却，只消耗装药量。
- 将“符文发射器”整体改名为“炼金台”。
- 炼金台新增 Tab：**药剂炼成**。
- 玩家可在药剂炼成 Tab 中选择多个符文进行融合，生成药剂法术。

建议遗物字段：

```js
{
    id: 'relic_sage_apothecary',
    name: '贤者药匣',
    effect: 'unlock_potion_alchemy',
    rarity: 'legendary',
    maxStacks: 1,
    desc: '解锁炼金台的药剂炼成。可消耗符文调制药剂法术；药剂法术不消耗 SP、无冷却，但有装药量。'
}
```

## 4. 药剂法术

### 4.1 数据结构

药剂法术不进入普通遗物技能冷却系统，建议独立定义 `POTION_SPELL_DB`：

```js
{
    id: 'potion_frost_seal',
    name: '霜封药剂',
    icon: '🧪',
    family: 'cryo',
    recipe: {
        runeElements: ['cryo', 'cryo'],
        minLevelSum: 2
    },
    maxCharges: 3,
    baseCharges: 2,
    desc: '投掷冰霜药剂，冻结所有敌人并降低温度。',
    params: {
        freezeDuration: 2,
        tempDown: 40
    }
}
```

运行态字段：

| 字段 | 含义 |
|---|---|
| `potionAlchemyUnlocked` | 是否已获得贤者药匣 |
| `preparedPotionSpell` | 当前装填药剂：`{ potionId, charges, maxCharges, quality, sourceRunes }` |
| `knownPotionSpellIds` | 已成功调制过的药剂图鉴，可选持久化 |
| `potionRecipeHistory` | 最近炼成记录，用于 UI 提示和调试 |

### 4.2 装填与弃置规则

贤者药匣初版只有 1 个药剂槽，因此调制新法术时必须处理旧法术：

- 若 `preparedPotionSpell` 为空，确认炼成后直接写入新药剂或失败返还。
- 若 `preparedPotionSpell` 已有药剂，点击“确认炼成”时必须弹出二次确认：**新炼成会弃置当前药剂，剩余装药量不会返还。**
- 玩家确认后，旧药剂先被弃置，再消耗符文并解析新配方。
- 若新配方成功，写入新 `preparedPotionSpell`。
- 若新配方失败，旧药剂也不会恢复，只获得失败返还。
- 若新配方与旧药剂 `potionId` 相同，不叠加装药量，而是按新结果覆盖旧药剂；这让“重调同款药剂”成为刷新品质/装药量的选择。

这条规则让药剂线形成清晰取舍：继续用旧药剂，还是赌一瓶更适合当前战斗的法术。

### 4.3 装药量显示

药剂技能槽中原本显示 SP 消耗的位置改为显示装药量，例如 `2/3`。

图标表现建议：

- 图标底图仍显示药剂法术图标。
- 使用垂直遮罩表达剩余装药量：`charges / maxCharges` 越低，药瓶内发光液体越少。
- 失去最后 1 次装药后，图标进入空瓶状态，按钮禁用。
- 若没有装填药剂，显示空药匣图标与 `0/0`。

实现上可以使用两层 DOM：

```html
<span class="potion-icon-shell">
  <img class="potion-icon-base" src="...">
  <span class="potion-charge-mask" style="height: 66%"></span>
</span>
```

普通技能继续显示 SP cost 和冷却遮罩；只有药剂技能槽显示装药量。

## 5. 药剂炼成 Tab

### 5.1 入口命名

现有“符文发射器”面板改名为 **炼金台**。首版可以保留内部 DOM id / 函数名 `rune_launcher`，但用户可见文案改为炼金台，避免一次性大规模重命名导致风险。

炼金台建议 Tab：

| Tab | 用途 |
|---|---|
| 符文配置 | 现有 3x3 符文网格与词条 |
| 符文管理 | 合成、重铸、库存 |
| 词条图鉴 | 现有词条图鉴 |
| 药剂炼成 | 新增，获得贤者药匣后显示 |

### 5.2 炼成流程

1. 玩家进入“药剂炼成”Tab。
2. 从符文库存选择 2-4 枚符文投入药匣。
3. UI 根据当前投入符文实时预览：
   - 可形成药剂：显示药剂名、效果、装药量、品质。
   - 无法形成药剂：显示“配方不稳定”，提示将返还部分局内货币。
4. 若当前已有药剂，确认按钮显示“弃置旧药剂并炼成”，并给出旧药剂剩余装药量提示。
5. 玩家确认炼成。
6. 若已有旧药剂，先弃置旧 `preparedPotionSpell`。
7. 符文立即消耗。
8. 若配方成立，写入新的 `preparedPotionSpell`。
9. 若配方失败，按规则返还部分局内货币，药剂槽保持空瓶。

### 5.3 失败规则

失败不是免费试错。确认炼成后：

- 投入符文全部消耗。
- 不生成药剂法术。
- 返还一部分局内货币，建议为投入符文估值的 30%-40%。
- 初版建议固定 `CONFIG.gameplay.potionAlchemyFailRefundRatio = 0.35`。

返还货币建议使用当前局内货币，而不是永久符文碎片，避免玩家把失败炼成当成符文转永久资源的漏洞。

失败返还建议公式：

```js
refund = floor(sum(runeValue(rune)) * potionAlchemyFailRefundRatio)
```

`runeValue` 初版可简化为 `level * 8` 局内货币；之后再根据稀有度加权。失败返还不能超过本次投入符文估值的 50%。

## 6. 配方设计

药剂配方应比符文词条更宽松，避免玩家频繁失败。建议初版使用“元素组合 + 等级总和 + 稀有关键词”的匹配方式，而不是固定顺序。

### 6.1 配方解析顺序

配方解析建议从强到弱匹配：

1. **专属配方**：精确元素组合或指定符文组合，生成高识别度药剂。
2. **元素家族配方**：同元素或相邻元素组合，生成稳定常规药剂。
3. **机制标签配方**：根据 `affinity_tags` 识别控制、爆发、召唤、回响等方向。
4. **失败配方**：不满足任何药剂条件，进入失败返还。

同一组符文命中多个配方时，优先级按 `recipe.priority`，再按 `levelSum`，再按投入符文数量判断。UI 预览必须显示最终将生成的唯一结果。

### 6.2 基础药剂清单

| 药剂 | 配方 | 装药量 | 效果方向 |
|---|---|---:|---|
| 霜封药剂 | 冰 + 冰，等级和 ≥ 2 | 2 | 冻结 / 降温 |
| 熔火药剂 | 火 + 火，等级和 ≥ 2 | 2 | 升温 / 过热 |
| 雷引药剂 | 雷 + 任意导电系，等级和 ≥ 2 | 2 | 感电 / 闪电链 |
| 剑影药剂 | 穿透 + 穿透 / 穿透 + 散射 | 2 | 飞剑斩击 |
| 坍缩药剂 | 弹跳 + 火 / 弹跳 + 超载 | 1 | AOE / 击退 |
| 回声药剂 | 回响 + 任意 | 3 | 复制下一次药剂或子弹效果 |
| 毒雾药剂 | 毒 + 毒 / 毒 + 散射 | 2 | 毒层扩散 / 持续削甲 |
| 棱镜药剂 | 激光 + 任意二级元素，等级和 ≥ 4 | 1 | 精准贯穿 / 破绽推进 |
| 过载药剂 | 超载 + 火 / 超载 + 雷 | 1 | 高爆发 / 自带副作用 |

品质建议：

- `quality = min(3, floor(levelSum / runeCount))`。
- 品质影响 `charges` 或参数强度，优先影响装药量，玩家更容易感知。
- 同元素高纯配方给更多装药量，复合配方给更强效果但装药量少。

### 6.3 品质与装药量

药剂结果由三个值共同决定：

| 值 | 来源 | 作用 |
|---|---|---|
| `quality` | 投入符文平均等级，1-3 | 提升参数强度 |
| `baseCharges` | 药剂定义 | 决定基础使用次数 |
| `chargeBonus` | 高纯度、同族符文、遗物加成 | 额外装药量 |

建议公式：

```js
quality = clamp(1, 3, floor(levelSum / runeCount))
purityBonus = dominantElementCount === runeCount ? 1 : 0
charges = clamp(1, maxCharges, baseCharges + purityBonus + qualityChargeBonus)
```

其中 `qualityChargeBonus` 初版只在 `quality === 3` 时 +1，避免高等级符文过早把药剂次数堆得过高。

## 7. 法术效果期望

药剂法术应该是“短期战术工具”，不是常规技能的下位替代。它们没有 SP 和冷却，所以效果必须更明确、更窄、更受次数限制。

### 7.1 效果定位

| 类型 | 期望用途 | 强度边界 |
|---|---|---|
| 控场药剂 | 给玩家争取一轮瞄准或防线缓冲 | 控制时间短于遗物技能，但可无 SP 快速补救 |
| 状态药剂 | 给敌人施加温度、感电、毒、易伤等状态 | 主要服务后续子弹，不直接清场 |
| 爆发药剂 | 处理残血群体或关键精英 | 装药量少，范围或伤害受品质限制 |
| 改弹药剂 | 强化下一发子弹或下一次命中 | 不直接造成大量伤害，依赖玩家打中 |
| 召唤药剂 | 临时生成飞剑、回响、护盾等对象 | 数量小、持续短，避免压过遗物技能 |

### 7.2 药剂效果细化

| 药剂 | Lv1 期望 | Lv2 期望 | Lv3 期望 |
|---|---|---|---|
| 霜封药剂 | 全体降温，短冻结高温敌人 | 冻结时间增加，附带少量易伤 | 冻结后首段物理/穿透伤害加深 |
| 熔火药剂 | 全体升温，接近过热阈值 | 对已燃烧目标追加伤害 | 对过热目标触发小范围爆燃 |
| 雷引药剂 | 给血量最高敌人感电并触发小链 | 链数增加，命中精英优先 | 链路命中后短暂削弱护盾 |
| 剑影药剂 | 召 2 道飞剑斩击随机目标 | 飞剑优先精英，伤害提高 | 飞剑命中后留下短暂裂痕易伤 |
| 坍缩药剂 | 小范围拉拽并造成 AOE | 范围扩大，敌人上推半格 | 对大型敌人额外破甲但仅 1 装药 |
| 回声药剂 | 下一次药剂或子弹效果有概率复制 | 复制概率提高 | 复制效果继承更多属性但不复制自身 |
| 毒雾药剂 | 施加毒层并向邻近敌人扩散 | 扩散半径提高 | 毒层侵蚀护盾和活体护甲 |
| 棱镜药剂 | 下一发激光/穿透获得精准贯穿 | 破绽推进提高 | 命中 Boss 破绽谱时额外进度 |
| 过载药剂 | 高伤害小爆炸 | 范围和伤害提高 | 额外震屏/击退，但可能降低装药量 |

### 7.3 副作用与稀有药剂

高强度药剂可以有轻副作用，但首版只用于少数稀有配方：

- 过载类：装药量固定 1，释放后清空少量临时技能充能。
- 坍缩类：对敌人强控制，但伤害较低或范围不稳定。
- 回声类：不能复制回声药剂自身，避免无限循环。
- Boss 破绽类：只推进破绽，不直接造成高额伤害。

## 8. 与 SP 的关系

贤者药匣的药剂技能不消耗 SP，也没有冷却，这一点必须和普通遗物技能明确区分。

因此技能栏需要支持两种 cost badge：

| 技能类型 | badge 内容 |
|---|---|
| 普通遗物技能 | `SP 2` |
| 药剂技能 | `2/3` 装药量 |

SP 仍然通过战斗充能和技能点槽获得，主要服务普通遗物技能。药剂线则服务“符文库存 -> 临时法术”的构筑转换。

## 9. UI 与交互状态

### 9.1 药剂炼成状态

药剂炼成 Tab 至少需要 5 种清晰状态：

| 状态 | UI 表现 |
|---|---|
| 未获得贤者药匣 | Tab 隐藏，或显示锁定提示 |
| 未投入符文 | 空药匣、符文库存、配方提示 |
| 可炼成 | 显示药剂预览、装药量、品质、确认按钮 |
| 不稳定配方 | 显示失败返还数额、确认按钮使用警告色 |
| 已有药剂 | 顶部显示当前药剂与剩余装药量，确认新炼成时提示会弃置 |

### 9.2 战斗技能栏状态

药剂技能槽建议固定在普通技能栏旁边，避免与遗物技能混排造成 badge 语义混乱。

- 普通技能：图标 + `SP n` + 冷却遮罩。
- 药剂技能：图标 + `charges/maxCharges` + 药瓶液面遮罩。
- 空药剂：空瓶图标 + `0/0`，点击可提示“在炼金台调制药剂”。
- 最后一发药剂释放后：图标变空瓶，同时弹出短提示“药剂已用尽”。

## 10. 边界规则

- 战斗中不能调制药剂，只能释放已装填药剂。
- 调制确认后不可撤销，符文消耗不可回滚。
- 成功调制新药剂会覆盖旧药剂；失败调制会清空旧药剂。
- 药剂装药量不跨局保留；是否跨回合保留可按难度调，初版建议跨回合保留、本局结束清空。
- 若玩家获得贤者药匣时已有符文库存，应立即在炼金台显示“药剂炼成”入口，不强制弹窗。
- 若旧存档没有 `preparedPotionSpell` 字段，初始化为空。

## 11. 实施路线

### Phase 1：普通技能遗物化

- `combat_recomputeActiveSkills()` 改为只从 `unlockRelic` 和旧存档购买记录计算普通技能池。
- `SKILL_DB` 统一使用 `spCost` 和 `cooldownSec` 字段；兼容读取旧 `cost`。
- 新增 `skillCooldowns`，`combat_activateSkill()` 增加冷却检查和冷却遮罩事件。
- 原 `runeword` 技能迁移到新遗物，或先标记为待迁移但不再由新词条解锁。

### Phase 2：贤者药匣与 UI 文案

- 新增遗物 `relic_sage_apothecary`。
- 用户可见“符文发射器”文案改为“炼金台”。
- 炼金台新增“药剂炼成”Tab，仅在获得贤者药匣后显示。
- 技能栏支持普通技能 SP badge 与药剂技能 charge badge。

### Phase 3：药剂炼成逻辑

- 新增 `POTION_SPELL_DB` 和配方匹配函数。
- 新增 `preparedPotionSpell` 运行态和存档兼容。
- 实现符文选择、预览、确认、成功装填、失败返还。
- 药剂释放复用现有技能效果分发，但不扣 SP、不写冷却。

### Phase 4：反馈与测试

- 真理之书新增“遗物技能”和“药剂法术”说明。
- 训练场新增场景：遗物技能冷却、SP 不足、药剂有装药量、药剂空瓶、炼成失败返还。
- UI 验证移动端药瓶遮罩、冷却遮罩、SP badge 不重叠。

## 12. 风险与约束

- 药剂失败必须消耗符文，否则配方探索没有成本。
- 失败返还只能返还局内货币，不能返还永久货币。
- 药剂技能无冷却无 SP，因此必须受装药量严格限制。
- 普通技能必须继续有 SP 和冷却，否则会和药剂线抢定位。
- 首版不建议重命名内部文件 `rune_launcher.js`，只改用户可见文案；等功能稳定后再做技术重命名。

## 13. 推荐最终口径

- **技能跟着遗物走**：遗物是主动能力的主要解锁来源。
- **SP 服务遗物技能**：强技能消耗 SP，并用冷却控制节奏。
- **贤者药匣开启药剂线**：药剂法术来自符文融合，不消耗 SP、无冷却，但有装药量。
- **炼金台成为构筑中枢**：现有符文配置、管理、词条图鉴保留，并新增药剂炼成。

这版比“符文解锁技能”更清楚，也比“所有魔法都靠炼金合成”更轻。遗物负责长期能力，SP 负责战斗节奏，药剂负责把多余符文转化成一次性战术法术。
