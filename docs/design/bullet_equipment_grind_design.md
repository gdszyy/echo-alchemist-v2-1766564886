# 子弹装备化与原质研磨设计草案

> 目标：保留研磨阶段的物理落珠玩法，但把触发方式解释为“观测并稳定一条原质流脉”。玩家在真理之书/炼金炉的观测中，从本轮出现的几条原质流脉里选择一条；该流脉析出一组原质胚珠，同一时间进入钉盘研磨。每颗胚珠独立收集属性，最终凝结成一个魔药弹列表。钉盘作为单局内的核心养成工坊，会随对局增加行数，并在钉子被同化后逐步固化属性。子弹可以进一步成为可持久养成的装备；符文不再默认全局生效，而是可以消耗并嵌入单枚子弹，让符文组合只影响该子弹。

## 1. 设计判断

当前系统里，`marbleQueue` 通过研磨收集属性，最后编译成一次性的 `ammoQueue`。这个结构的优点是反馈直接，但缺点也明显：

- 每回合子弹像临时配方，玩家很难对“某一枚子弹”产生长期投入。
- 符文词条现在以全局 `activeRunewordEffects` 生效，强度容易变成整套弹药同时膨胀。
- 纯净精华的“消耗符文给弹珠加属性”和混沌精华的“跳过研磨升级充能子弹”已经在向子弹养成靠拢，但规则仍是特殊分支。

新的核心判断是：**研磨阶段不取消，改成“选择一条原质流脉，然后用本局成长起来的钉盘把其中的胚珠研磨成魔药弹列表”的过程。** 子弹可以继续向局内装备演化，但第一版应先稳住“原质观测 + 钉盘成长 + 多胚珠同时研磨 + 输出子弹列表”的手感。

## 1.1 世界观解释层

所有机制都应先有世界内解释，再落成 UI 和代码命名。玩家不应看到外部商业化或概率系统词，而是看到炼金、回声、原质与炉盘的语言。

| 机制层 | 世界内名称 | 玩家理解 |
|---|---|---|
| 系统随机性 | 原质潮汐 / 原质流脉 | 每回合炼金炉会显露几条可稳定的原质流，炼金师只能固定其中一条 |
| 弹珠组 | 原质胚珠 | 原质流脉被稳定后析出的胚珠，会进入钉盘接受研磨 |
| 强度分层 | 纯度 | 流脉越纯，胚珠越多、越特殊，但扰动也更强 |
| 多弹珠同落 | 共振研磨 | 多颗胚珠同时进入炉盘，彼此不是复制品，而是同一条流脉的不同结晶 |
| 钉盘成长 | 炉盘拓印 / 炼金矩阵扩展 | 战斗推进后，炼金炉能承载更深的矩阵行数 |
| 钉子同化 | 属性刻蚀 / 炉钉同化 | 胚珠或符文把属性刻进炉钉，之后本局都会保留 |
| 钉子防连刷 | 回声饱和 | 同一颗胚珠连续撞同一炉钉时，回声尚未散去，无法再次拓印属性 |
| 子弹列表 | 魔药弹列 / 装填序列 | 研磨完成后，胚珠凝结成可装填的魔药弹 |
| 子弹确认 | 晶石充能 / 装填校准 | 炼金师从凝结出的魔药弹中选择本回合注入晶石核心的顺序 |
| 每回合三发 | 三枚晶石核心充能位 | 炼金发射器默认只能一次充能三枚魔药弹，发射后对应核心位耗尽 |
| 符文嵌入 | 符文封印 | 把符文消耗并封入单枚魔药弹，使其获得局部词条 |

推荐 UI 文案方向：

- “观测原质流脉”
- “稳定此流脉”
- “释放原质胚珠”
- “炉盘已扩展”
- “炉钉完成火焰刻蚀”
- “回声饱和：需触碰其他炉钉后再次拓印”
- “魔药弹已凝结”
- “选择晶石充能序列”
- “晶石核心已充能”
- “核心耗尽：等待下一次充能”

这些词能把机制全部放回《Echo Alchemist》的炼金/回声背景下：玩家不是在购买概率道具，而是在观测短暂出现的原质潮汐，并用自己这一局养成的炼金炉把它固定成武器。

## 2. 新核心循环

推荐第一版循环：

1. 回合开始或命运时刻：真理之书观测到 3 条“原质流脉”，每条流脉由若干原质胚珠、纯度偏向和特殊扰动组成。
2. 研磨阶段：玩家选择 1 条原质流脉后，一次性释放其中所有胚珠。胚珠同屏一起下落，而不是逐个发射。
3. 钉盘加工：本局钉盘用已解锁行数、已同化属性钉和特殊槽影响落珠结果。
4. 落珠结算：每颗弹珠独立记录自己收集到的属性、命中次数、多重触发和特殊材料。
5. 生成子弹列表：所有胚珠停止后，逐颗胚珠编译成 recipe，得到本回合待充能的魔药弹列。
6. 晶石充能：炼金发射器默认只有 3 个晶石核心充能位，玩家从魔药弹列中选择最多 3 枚注入核心，并决定发射顺序；其余可转为材料、暂存或丢弃。
7. 战斗阶段：玩家按晶石核心序列发射本回合魔药弹。每次发射都会耗尽对应核心位，核心位未重新充能前不能再次发射。后续版本再把这些子弹升级为可持久装备。

这样原质观测决定的是“本次研磨的起手资源和风险”，钉盘决定“这局长期培养出的加工倾向”，物理落珠决定最终魔药弹质量。选到高纯度流脉不等于直接拿到强弹，玩家还要看胚珠落点、钉盘布局和多胚珠之间的触发结果。

## 2.1 原质流脉结构

原质流脉不是直接给子弹，而是给一组原质胚珠和本次研磨的扰动参数。

```js
{
  id: string,
  purity: 'turbid' | 'clear' | 'bright' | 'perfect',
  motes: [
    { type: 'pyro', level: 1, tags: ['element'] },
    { type: 'bounce', level: 1, tags: ['kinetic'] },
    { type: 'laser', level: 1, tags: ['rare_core'] }
  ],
  dropPattern: 'fan' | 'line' | 'cluster' | 'staggered',
  disturbances: {
    bonusEnergy: number,
    extraAttributeChance: number,
    splitOnFirstHit: boolean,
    maxOutputBullets: number
  }
}
```

观测 UI 应展示的是“这条流脉会析出哪些胚珠、数量、纯度、可能产出倾向”，而不是展示最终子弹。最终子弹必须由研磨过程生成。

## 2.2 多弹珠同时下落

第一版建议每条流脉析出 2-5 颗胚珠：

| 流脉纯度 | 胚珠数量 | 特殊胚珠概率 | 主要体验 |
|---|---:|---:|---|
| 浑浊 turbid | 2-3 | 低 | 稳定、可读 |
| 清澈 clear | 3 | 中 | 属性更明确 |
| 明亮 bright | 3-4 | 高 | 容易产出强子弹 |
| 完美 perfect | 4-5 | 很高 | 高噪声、高上限 |

所有弹珠共享同一个 `GrindSession`，但每颗弹珠有自己的子会话：

```js
{
  sessionId: string,
  activeBalls: number,
  ballResults: [
    {
      ballUid: string,
      marbleType: string,
      collected: [],
      multicast: 0,
      totalHits: 0,
      lastScoringPegUid: null
    }
  ],
  outputRecipes: []
}
```

`currentSession.collected` 这种单数组结构需要拆成 `ballResults[i].collected`，否则多弹珠同时落下时会把所有属性混在同一枚子弹上。

## 2.3 取消钉子冷却，改为单弹珠防连刷

现有钉子有 `cooldownTimer` / `dynamicCooldown`，会导致多弹珠同时下落时互相抢触发。新规则建议取消普通属性钉子的全局冷却：

- 普通属性钉不再因为被 A 弹珠撞到就进入全局冷却。
- 每颗弹珠记录自己的 `lastScoringPegUid`。
- 当同一颗弹珠连续碰撞同一个钉子时，只发生物理反弹，不增加属性、能量、命中收益。
- 这颗弹珠必须先有效碰撞另一个钉子，才能再次从前一个钉子获得收益。
- 不同弹珠之间互不影响：A 弹珠刚触发过某钉子，B 弹珠仍可立刻从该钉子获得收益。

伪代码：

```js
function tryScorePegForBall(ball, peg) {
  if (peg.frozenTurns > 0) return false;
  if (ball.lastScoringPegUid === peg.uid) {
    return false; // 只反弹，不给属性和能量
  }
  ball.lastScoringPegUid = peg.uid;
  addPegRewardToBallResult(ball, peg);
  return true;
}
```

这个规则保留了防刷保护，但不惩罚多弹珠同屏，也不会出现“前一颗弹珠刚撞过，后一颗弹珠撞上却什么都没有”的挫败感。

特殊槽、转盘、一次性奖励区可以保留自己的触发限制，因为它们不是普通属性钉。第一版只要求普通 `Peg` 的属性/能量收益从全局冷却改成单弹珠防连刷。

## 2.4 钉盘局内成长

钉盘应成为本局的长期养成要素，承担“我这局把炼金机器改造成什么样”的体验。原质流脉是输入，钉盘是加工工坊，最终子弹列表是输出。

推荐第一版把钉盘成长拆成两个维度：

- **行数成长**：随回合、Boss、商店或清屏奖励解锁更多钉盘行数。
- **属性固化**：普通钉子被同化成属性钉后，在本局内基本固化，成为后续研磨的稳定产出点。

行数成长建议：

| 时机 | 钉盘变化 | 玩家感受 |
|---|---|---|
| 开局 | 3-4 行基础钉盘 | 短路径、结果简单 |
| Round 3-5 | 解锁 1 行 | 研磨开始变长，属性积累更明显 |
| 首个 Boss 后 | 解锁 1-2 行或特殊槽位 | 战胜 Boss 后机器升级 |
| 中后期商店/奖励 | 解锁底部奖励区、侧翼行或特殊模块 | 玩家有定向养成选择 |

行数增加不只是增加收益，也会改变落珠路径。越深的钉盘越适合多弹珠同时下落，因为弹珠之间会分流，最终子弹差异更明显。

属性固化建议：

- 普通钉子初始为 `normal/white`，不提供强属性，只提供基础命中或少量能量。
- 当弹珠、符文、精华或模块效果触发“同化”时，某个普通钉子转化为属性钉，如 `pyro`、`cryo`、`bounce`、`pierce`。
- 被同化后的钉子在本局内保持该属性，后续所有原质流脉都能利用它。
- 同化优先发生在当前弹珠实际碰撞过的钉子附近，让玩家感觉属性是“被炼出来并留在机器上”的。
- 同化不应频繁覆盖；覆盖需要特定资源，如纯净精华、商店重铸或高稀有符文。

这会让玩家形成长期规划：前期把钉盘染成火/弹跳/穿透方向，中期开始选择更适配的原质流脉，后期同一套钉盘会稳定加工出某类子弹。

## 2.5 钉盘成长与原质流脉的关系

原质流脉选择应该和钉盘状态强绑定：

- 如果钉盘已经有大量火钉，玩家会更愿意稳定多胚珠、高路径长度或火系胚珠流脉。
- 如果钉盘偏弹跳/穿透，玩家会优先选择能多次横向穿过钉盘的流脉。
- 如果钉盘刚解锁新行，玩家会倾向选择数量多、分散落点的流脉，去探索和同化新区域。
- 如果玩家观测到和钉盘方向不匹配的流脉，也可以选择它作为“转型机会”，通过同化把钉盘染向新属性。

这能让系统随机性成为世界内的“原质潮汐观测”，并和局内成长形成闭环：**原质流脉给短期输入，钉盘给长期偏置，子弹列表给战斗输出。**

## 3. 子弹装备模型

长期版本建议新增局内数据结构 `BulletEquipment`，不要继续把 `MarbleDefinition` 扩成更大的混合对象。但在“原质流脉第一版”里，可以先把 `BulletEquipment` 当作后续目标，当前只需要把多弹珠结果编译成 recipe 列表。

```js
{
  uid: string,
  archetype: string,        // damage/bounce/pierce/scatter/pyro/cryo/laser/explosive 等
  rarity: 'common' | 'rare' | 'epic' | 'legendary',
  level: number,
  xp: number,
  baseStats: {
    damage: number,
    bounce: number,
    pierce: number,
    scatter: number,
    pyro: number,
    cryo: number,
    lightning: number,
    laser: number,
    wind: number
  },
  affixes: string[],        // 轻量词缀，如首发加成、击杀成长、Boss 增伤
  runeSlots: [
    { index: 0, rune: { id: string, level: number } | null, locked: boolean }
  ],
  localRuneword: null | {
    id: string,
    effectId: string,
    level: number,
    params: object
  },
  timesFired: number,
  kills: number,
  locked: boolean
}
```

`ammoQueue` 仍然可以存在，但它变成战斗阶段的临时发射队列。原质流脉第一版里，本轮多弹珠落珠结果应先进入“待充能魔药弹列”，再由玩家选择最多 3 枚写入晶石核心：

```js
pendingBullets = grindSession.ballResults.map(result => compileBallResultToRecipe(result));
chargedCoreSlots = selectBulletsForCrystalCore(pendingBullets, 3);
ammoQueue = chargedCoreSlots.map(slot => slot.recipe);
```

后续子弹装备版本里，来源再升级为装备栏和晶石核心共同决定：

```js
chargedCoreSlots = chargeCrystalCore(equippedBullets.slice(0, crystalCoreCapacity));
ammoQueue = chargedCoreSlots.map(slot => compileBulletToRecipe(slot.bullet));
```

如果 recipe 来自装备子弹，需要带上 `_bulletUid` 和 `_localRunewordEffect`，方便战斗结束后把经验、击杀数等写回子弹本体。如果 recipe 来自本轮研磨结果，则只需要带上 `_sourceBallUid`，用于 UI 回看“这枚子弹由哪颗弹珠产出”。

## 4. 品阶与符文槽

第一版建议采用“炼成品阶 = 稳定潜力上限”，而不是单纯数值碾压。玩家看到的是魔药弹被炼成后的稳定度，不是外部系统里的价值标签：

| 炼成品阶 | 初始槽位 | 升级后上限 | 词条能力 | 定位 |
|---|---:|---:|---|---|
| 粗炼 common | 1 | 2 | 不能形成词条 | 前期过渡，直接加属性 |
| 精炼 rare | 2 | 3 | 解锁后可形成 1 个词条 | 成型起点 |
| 秘炼 epic | 3 | 4 | 默认可形成 1 个词条 | 主力养成 |
| 真炼 legendary | 4 | 5 | 1 个词条 + 催化槽 | 构筑核心 |

词条需要至少 3 个符文槽。这样粗炼/精炼子弹先承担“属性成长”，秘炼/真炼承担“机制改变”。

如果测试发现词条来得太晚，可以把表调整为 rare 初始 3 槽、epic 4 槽、legendary 5 槽，但第一版不建议一开始就这么宽，避免局部词条上线后强度失控。

## 5. 符文嵌入规则

符文嵌入应同时满足两个目标：让符文成为明确消耗品，同时给子弹一个可读的成长边界。

推荐规则：

- 玩家选择一枚子弹和一个空符文槽，消耗 1 枚库存符文并写入该槽。
- 嵌入符文立即给该子弹增加对应属性：`rune.level * rune.baseStatPerLevel`。
- 已嵌入符文参与该子弹的局部词条匹配。
- 替换已嵌入符文会摧毁旧符文，并返还少量符文碎片，避免免费反复插拔。
- 锁定子弹不能被分解或覆盖，但仍可嵌入空槽。

不要做“无限合入加属性”。如果符文可以不占槽地无限消耗并堆属性，子弹装备化会迅速变成单枚子弹数值滚雪球。槽位就是必要的强度闸门。

## 6. 单子弹词条

现有 `RUNEWORD_DB` 可以复用，但激活范围从全局变为单枚子弹。

第一版推荐限制：

- 每枚子弹最多激活 1 个 `localRuneword`。
- 词条等级由参与符文等级决定，建议 `level = min(3, floor(avg(runeLevels)))`。
- 4/5 槽位不是默认多词条，而是催化槽：可以提高词条等级、降低负面代价或追加小参数。
- 战斗中只在该子弹发射时读取 `recipe._localRunewordEffect`。

示例：

- 一枚史诗穿透子弹嵌入 `pierce + pyro + pierce`，激活“嗜血初锋”。只有这枚子弹享受击杀成长和元素惩罚。
- 一枚传说弹跳子弹嵌入 `bounce + lightning + bounce + scatter`，前三枚激活“散射矩阵”，第四枚作为催化槽减少伤害惩罚。

这种局部化能保留符文组合的爽点，但不会让所有子弹同时吃到同一套全局词条。

## 7. 原质观测阶段

研磨阶段保留。进入研磨前，玩家通过真理之书或炼金炉观测本轮可稳定的原质流脉。玩家看到的是几条短暂出现、可被稳定下来的原质谱系。

基础流程：

1. 观测 3 条可稳定的原质流脉。
2. 玩家选择其中 1 条进行稳定。
3. 系统按流脉内 `motes` 和 `dropPattern` 创建多颗 `DropBall`。
4. 多颗弹珠同时下落，分别收集属性。
5. 所有弹珠结束后，按弹珠结果生成子弹列表。
6. 玩家确认子弹列表进入战斗；若列表超过上限，则选择保留的几枚。

可观测流脉由三层决定：

- 弹珠池：复用现有弹珠类型，如 damage、bounce、pierce、scatter、pyro、cryo、laser、explosive、matryoshka、rainbow、echo、venom、overcharge。
- 流脉纯度：决定弹珠数量、特殊弹珠概率、dropPattern 和额外扰动。
- 智能偏向：复用现有符文智能权重思路，根据玩家近期伤害构成和当前敌人词缀，提高补足短板或强化主流派的流脉权重。

建议初始观测权重：

| 阶段 | 浑浊 | 清澈 | 明亮 | 完美 |
|---|---:|---:|---:|---:|
| Round 1-4 | 78% | 20% | 2% | 0% |
| Round 5-10 | 58% | 32% | 9% | 1% |
| Round 11-16 | 42% | 38% | 17% | 3% |
| Round 17+ | 30% | 40% | 24% | 6% |

Boss 后、纯净精华、商店高级货架可以提高“原质流脉纯度下限”，而不是直接给固定强子弹。

## 7.1 子弹列表生成

多弹珠研磨结束后，输出规则应简单、可预期：

- 每颗原始弹珠默认生成 1 枚子弹。
- 分裂、套娃、回响等效果可以新增子弹，但受 `maxOutputBullets` 限制。
- 若某颗弹珠没有收集任何属性，仍生成基础伤害子弹，避免空结果。
- 子弹排序默认按弹珠落下顺序，也可以在确认 UI 里让玩家拖拽排序。
- 超出晶石核心充能位的子弹进入“候补区”，玩家选择是否暂存，未保留的转为少量材料。第一版可继续用现有 `bulletCap` 承接这个数量上限，但 UI 语义应显示为“核心充能位”。

这比“所有弹珠混合成一枚大子弹”更好，因为多弹珠同时下落的视觉结果能一一对应到最终子弹列表，玩家更容易理解每枚子弹从哪里来。

## 8. 精华定位

把现有两个特殊流程收敛成子弹养成的两个风格。

### 混沌精华

定位：高波动、改造当前子弹、赌上限。

可选效果：

- 可观测流脉 +1，但流脉内胚珠与扰动更不稳定。
- 对当前装备子弹触发“混沌转轮校准”：转轮落在当前已有属性时强化，落在空白属性时给少量新属性。
- 有概率增加一个临时过载槽，但也可能附加负面词缀。

现有 `sys_skipChaosEssenceUpgrade()` 可以迁移为混沌精华的子弹改造动作。

### 纯净精华

定位：定向、安全、减少随机损失。

可选效果：

- 指定一个弹珠类型或一个已有子弹作为目标，提高同类原质流脉出现概率。
- 本次嵌入符文替换时不摧毁旧符文，或返还更多碎片。
- 可观测原质流脉至少为清澈纯度。
- 直接获得一枚指定属性符文，并可立刻嵌入一枚子弹。

现有“消耗符文给弹珠追加属性”的 pure essence 分支可以迁移为常规的“给子弹嵌符文”交互。

## 9. 晶石核心、子弹栏与仓库

建议把当前“每回合最多 3 发”的核心手感解释为晶石能量驱动，而不是 UI 硬限制：

- 炼金发射器由晶石核心驱动，每次发射都必须消耗 1 枚已充能核心位。
- 默认发射器只有 3 个晶石核心充能位，因此一回合最多完成 3 次发射。
- 研磨结束后，玩家不是单纯“选 3 枚子弹”，而是在给 3 个晶石核心位注入魔药弹。
- 发射后对应核心位进入耗尽状态；没有新的研磨/充能流程时，不能在同一回合继续发射。
- 晶石核心位：基础 3 枚，对应一回合可发射次数，沿用 `CONFIG.gameplay.selectionReq` 和 `bulletCapBonus` 作为第一版实现映射。
- 装备栏/仓库：负责保存可养成的魔药弹，不应和“本回合可发射次数”在玩家理解上混为一谈。
- 仓库：基础 6 枚，商店或遗物可扩容。
- 战斗开始：已充能核心序列编译为 `ammoQueue`，按顺序发射。
- 战斗结束：子弹本体保留，并获得经验/击杀记录。

这能把当前 `ammoQueue` 的很多 UI 和战斗逻辑保留下来，只是 `ammoQueue` 的来源从 `marbleQueue` 改成“已完成晶石充能的魔药弹序列”。如果后续要扩展发射次数，应优先解释为晶石核心扩容、备用核心、快速再充能或遗物提供的临时核心位。

## 10. 成长与材料

为了避免只有观测随机性而缺少养成，子弹需要三个成长入口：

- 等级：发射、命中、击杀获得 XP；等级提升增加基础伤害或小属性。
- 槽位：达到等级门槛或消耗材料解锁当前品阶上限内的锁定槽。
- 词缀：消耗同品阶子弹材料重铸 1 个 affix。

材料来源：

- 分解待确认子弹。
- 分解仓库子弹。
- 清屏奖励。
- 商店购买。
- Boss 战利品。

不要让等级直接支配全部强度。更好的比例是：等级提供 30% 稳定成长，符文槽提供 40% 构筑方向，词缀/品阶提供 30% 上限差异。

## 11. 与现有系统的迁移关系

建议分阶段落地，避免一次性改穿 `game_phase.js`、`combat_system.js` 和 UI。

### Phase A：数据模型与适配器

- 新增 `bullet_inventory` 或 `bullet_equipment` 模块。
- 增加 `equippedBullets`、`bulletInventory` 存档字段。
- 实现 `compileBulletToRecipe(bullet)`，输出当前 recipe 结构。
- 新增“晶石充能序列”适配层，把玩家选择的最多 3 枚魔药弹编译为 `ammoQueue`。
- 战斗仍消费 `ammoQueue`，但 `phase_startCombatPhase()` 优先从已充能核心序列编译。

### Phase B：局部符文槽

- 实现子弹符文槽 UI 和嵌入/替换规则。
- 新增 `parseBulletRuneSlots(bullet)`，复用 `RUNE_DB` 和 `RUNEWORD_DB`。
- `combat_fireNextShot()` 在 recipe 上读取 `_localRunewordEffect`。
- 暂时保留全局 `runeGrid`，但战斗中避免全局词条和局部词条同时全量叠加。

### Phase C：研磨阶段改为原质观测

- `phase_startGatheringPhase()` 先进入原质流脉观测 UI，玩家确认后再初始化钉板和多胚珠下落。
- `marbleQueue` 从“逐个发射队列”改为“本次原质流脉析出的弹珠定义列表”。
- `currentSession` 拆成多弹珠结果结构，避免多颗弹珠共享同一个 `collected`。
- 普通 `Peg` 取消全局冷却，改为 `DropBall` 级别的 `lastScoringPegUid` 防连刷。
- `replaceAmmoContext` 后续可改造成“新生成子弹列表 vs 当前晶石充能序列”的确认上下文。

### Phase D：钉盘局内成长

- 新增本局钉盘成长状态，如 `pinboardUnlockedRows`、`pinboardAssimilatedPegs` 或写回现有模块 `pegStates`。
- 行数解锁通过回合、Boss、商店、清屏奖励驱动，初始化钉盘时读取该状态生成更多行。
- 普通钉子同化后把 `type/level/source` 写回持久钉盘状态，后续研磨重建钉盘时保持属性。
- 同化覆盖需要走明确资源入口，禁止普通碰撞频繁随机覆盖已固化属性。
- UI 需要展示“本局钉盘倾向”，例如火/冰/弹跳/穿透占比，帮助玩家选择原质流脉。

### Phase E：精华和商店重接入

- 混沌精华接入混沌转轮校准/变异。
- 纯净精华接入定向观测/安全嵌符文。
- 局内商店出售钉盘行数扩展、同化重铸、子弹槽位材料、仓库扩容和定向重铸。

### Phase F：旧全局符文发射器重定位

两个可选方向：

- 改成“子弹工坊”：管理子弹、符文嵌入、词条图鉴。
- 保留为“全局奥术阵列”，但只提供技能解锁或轻量全局共鸣，不再直接给所有子弹注入强词条。

第一版更推荐前者，规则更干净。

## 12. 平衡风险与约束

- 符文合入必须占槽，否则属性会无限堆叠。
- 单枚子弹默认最多 1 个词条，否则传奇 5 槽会迅速超过当前全局词条强度。
- 子弹装备本体持久，但每回合发射的是晶石核心内的临时 recipe，避免战斗逻辑直接修改装备对象。
- 三发限制来自晶石核心充能位，不应被表现为单纯的子弹栏容量；扩大发射次数必须有对应的晶石核心扩容或再充能来源。
- 高品阶应该代表潜力和槽位，不应该在基础伤害上完全碾压低品阶。
- 原质观测要有智能偏向，但不能完全定向，否则每局构筑过早收敛。
- 多弹珠同屏时，普通钉子不能再使用全局冷却，否则后落下的弹珠会被前一颗弹珠“吃掉收益”。
- 单弹珠防连刷只限制连续同钉收益，不限制物理碰撞，不应该让弹珠穿过钉子。
- 钉盘行数增长要控制节奏；过早解锁太深会让落珠时间变长、结果噪声过大。
- 钉子同化后应基本固化，但必须保留少量重铸入口，避免玩家早期染错方向后整局无法转型。
- 同化收益要与钉盘可读性绑定，UI 必须让玩家看懂当前钉盘已经偏向哪些属性。
- 旧 `activeRunewordEffects` 与新 `_localRunewordEffect` 必须有明确优先级，避免双重生效。

## 13. 第一版验收口径

第一版不追求所有旧玩法一次迁完，只要证明核心体验成立：

- 研磨开始前能展示 3 条可稳定的原质流脉。
- 选择原质流脉后，会同时释放其中多颗弹珠。
- 多颗弹珠各自收集属性，互不污染结果。
- 普通钉子无全局冷却；同一颗弹珠连续撞同一钉子不会重复获得属性/能量，撞过别的钉子后可重新触发。
- 钉盘能在局内增加行数，新增行数在后续研磨中真实参与落珠路径。
- 普通钉子被同化成属性钉后，属性在本局内保持，后续原质流脉能继续利用。
- 当前钉盘属性倾向在 UI 上可读，玩家能据此选择原质流脉。
- 所有弹珠结束后，能得到一个清晰的子弹列表。
- 子弹列表能进入晶石充能序列，编译为战斗 `ammoQueue`，并按核心位顺序发射。
- 若子弹数量超过上限，玩家能选择保留的子弹。

这个版本若好玩，再继续把混沌/纯净精华、商店、Boss 战利品和旧符文发射器完整迁移过去。
