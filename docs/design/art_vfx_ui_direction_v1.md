## 0. 结论

整个游戏统一到**一种像素精度**：手机上 1 个美术像素 ≈ 2 个 CSS 像素，严格按整数倍放大，不做任何平滑。具体做法：

- 敌人用 24×24 像素造型，造型就是血条，被打时像素裂开、掉落、碎掉。
- 特效**逻辑原样保留**，只把画法改成落在像素格上、用统一调色板，并补上原来没有的「元素合并」和「伤害分档」。
- UI 按新的「挖 → 整备 → 守」三段重做，统一成一套样式系统。

**最先要做的不是画新图**，而是修渲染底座。画面糊的头号原因是两层画布分辨率不一致、全程平滑缩放；底座不修，换什么素材都还是糊的。

## 2. 像素规格（全局唯一）

### 2.1 精度与缩放

- 设备像素整数倍 `k = round(2 × DPR)`：DPR 2 → 4，DPR 3 → 6，DPR 2.625 → 5。
- 逻辑分辨率 = `floor(CSS 宽 × DPR / k)`。375 宽约 187×333，430 宽约 215×382，PC 480 宽约 240×426。
- 整个世界先画进**一张逻辑分辨率的低清缓冲**，再一次性按 ×k 放大到屏幕，不逐精灵缩放。
- 物理坐标仍用浮点，只在绘制时取整。
- 两层画布都设 `imageSmoothingEnabled = false`，**每次改尺寸后重设**；CSS 加 `image-rendering: pixelated` 兜底。
- PixiJS 层改为逻辑分辨率、resolution 1、关闭 autoDensity、默认 NEAREST、开启像素取整。

### 2.2 尺寸网格

| 类别 | 美术像素 | 说明 |
|---|---|---|
| 普通敌人 | 24×24（22 轮廓 + 1 描边余量） | 一格约 26–30 美术像素 |
| 精英 | 24×24 | 靠轮廓 + 词条标记区分，不靠变大；除非机制上占多格 |
| Boss | 48×48（2×2 格）/ 72×72（3×3 格） | 与碰撞格一致，**不再放大超出碰撞框** |
| 钉 / 弹珠 | 4×4 / 6×6 | 对应碰撞半径 |
| 弹丸 | 3–6 | |
| 整备界面图标 | 24×24（显示 48 CSS px） | 两个信息点（主体 + 元素）以内 |
| 战斗 HUD 小图标 | 16×16 | **单独手绘**，不从 24 缩 |

**图标模糊的根因和规则**：16px 只装得下「一个符号 + 一个元素色」。要表达两个信息的图标（如带等级的设施）必须用 24px。

**混用精度**只允许一种情况：整块 UI 面板统一用 1 CSS px = 1 美术像素（正好 2:1），而且这块面板不压在战场上、原生按该尺寸绘制、登记在「精度登记表」里。战场上、单个精灵内部永远不混用。

### 2.3 调色板与三层分离

一张固定的约 48 色索引调色板：

- 1 个描边暗色。
- 每种元素一条 5 阶色带：火、冰、雷、毒、激光、回响，另留 2 条备用。
- 4 个背景中性色。

| 层 | 规则 | 目的 |
|---|---|---|
| 背景 | 只用低饱和中间明度，不用描边色，不用色带最亮 2 阶 | 退后 |
| 可交互（敌人 / 钉 / 弹珠 / 设施） | 全明度范围 + 自动 1px 四邻描边 | 突出 |
| 反馈（特效 / 数字） | 色带最亮阶 + 白；发光类不描边 | 最前 |

**可机检**：每个像素都在调色板内；背景层不含描边色和最亮 2 阶；DPR 2/3 截图中每个美术像素是均匀的 k×k 块。

## 3. 敌人：造型 = 碰撞 = 机制

### 3.1 设计契约

- **轮廓 = 碰撞边界**：轮廓在碰撞框内的填充率 0.6–0.9，出框不超过 1px。Boss 现在被刻意放大 1.18–1.72 倍画在碰撞框外（`docs/boss_sprite_redraw_asset_contract.md:232`），这条要改掉，看到哪里就能打到哪里。
- **机制能从造型读出**：每个词条对应**一个大的造型特征**，不再靠 `R:py` / `A:cr` 这类文字徽章。例如：
  - 护盾 = 外层甲片
  - 极速 = 前倾轮廓 + 尾迹
  - 增殖 = 身上的芽孢
  - 治愈 = 十字核心
- **保护特征**：眼睛、核心、词条标记这些「认出它是什么」的像素，最后才掉。

### 3.2 像素破碎血量（替代灰蓝液体）

**数据**：每种敌人一张共享底图；每个敌人用一个字节数组，按 2×2 簇（Boss 3×3）记录状态：0 完好 / 1 裂开 / 2 掉落。每张底图预计算一次移除顺序：由外向内，机制弱点优先，加固定种子抖动，同一种子顺序相同。

**映射**：
- 可移除池 = 实心簇 − 约 30% 的保护核心。
- 已掉落数 = floor((1 − 血量%) × 池大小)。
- 再往后约 10% 的簇显示为裂开（色带暗一阶）。
- 新掉落的簇按自身颜色生成下落碎屑。

**必须配的可读性补充**（可读性专家）：

1. **四个固定阶段** 100 / 75 / 50 / 25%，每阶是不同的裂纹**形状**（不是颜色）。同样的血量永远长得一样。
2. **瞄准预告**：拖动瞄准时，预计命中的敌人用闪烁描边标出会掉的部分；能打死的打上**形状标记**（骷髅或括号角），颜色只作辅助。
3. 悬停、长按或瞄准时显示**精确血量数字**。伤害数字照常显示，放在精灵上方，不压住保护核心。

**特例**：
- **Boss**：保留一条分段的阶段血条（例外），精灵只表现当前阶段内的残损；可按部位分块，阶段阈值掉大块。
- **护甲敌人**：外壳甲片先碎，外壳碎完才开始掉血量像素。
- **护盾**：只在防线上，不画在敌人身上。

**性能**：每个敌人一张 24×24 离屏缓冲，只在受伤状态变化时重画（脏标记），每帧 1:1 贴进低清缓冲；碎屑全局限量。

**验收（需真人）**：20 张冻结画面测验。
- 关预告：说出敌人处于哪一阶，±1 阶内正确率 ≥ 90%。
- 开预告：「下一发 10 伤害能打死谁」100% 答对。

## 4. 特效：逻辑保留，画法像素化，补合并与分档

### 4.1 保留还是改（四条全满足才可原样保留）

1. 画在反馈层，敌人活着时不画进敌人框内（命中 2 帧白闪例外）。
2. 对齐像素格并用最近邻缩放，或持续 ≤ 200ms。
3. 只用调色板颜色。
4. 不改变承载血量的像素颜色。

| 处理 | 对象 |
|---|---|
| **必须像素化** | 敌人与其受损、弹丸、敌人身上的持续状态（燃烧 / 感电 / 毒 / 风印）、护盾、设施、伤害数字字体、HUD 图标 |
| **量化后可保留** | 加色发光（在 1/4 分辨率画，再最近邻放大）、阶梯半径冲击波、按像素阶梯画的闪电、全屏闪光、共鸣描边脉冲 |
| **敌人身上必须去掉** | `enemyGloss`、敌人附近的 `shadowBlur`、Boss / 精英 / 词条外发光（`src/config.js` 约 1204–1292）、溢到精灵上的 `bulletGlow` |

用户问的「像素和现有特效不一定冲突」：**对**。发光、冲击波、闪电这类反馈层特效量化后可以留，冲突的只是「盖在敌人身上、改了敌人颜色」的那部分。

### 4.2 元素组合怎么合并

- **主元素** = 等级最高的元素（同级取先拾取的），决定弹体颜色和形状。
- **副元素**只出现在边缘或拖尾图案上；**第三元素**只出现在命中时的粒子图案上。
- 弹体最多 2 种色相；两色**用棋盘抖动交错，不做加色混合**，避免变成一团泥。
- 每种元素有唯一形状，靠形状区分而不是只靠颜色：火 = 火舌，冰 = 冰菱，雷 = 折线，毒 = 液滴，风 = 旋涡，激光 = 直线。

### 4.3 数值怎么体现（主炮、设施、炼成弹共用一把尺）

| 档 | 伤害 | 冲击半径 | 粒子上限（高档） | 震屏 | 数字 |
|---|---|---|---|---|---|
| T1 | < 15 | 0.5 格 | ≤ 6 | 无 | 小 |
| T2 | 15–44 | 0.8 格 | ≤ 12 | 无 | 中 |
| T3 | 45–99 | 1.2 格 | ≤ 24 | 2px / 100ms | 大 + 描边 |
| T4 | ≥ 100 | 最大 1.5 格 | ≤ 40 | 4px / 150ms | 大 + 弹跳 |

- **大小只由伤害决定**；来源（主炮 / 设施 / 炼成弹）靠数字边框区分。
- 数字改为像素位图字体（3×5 或 5×7），画进低清缓冲。现在每个敌人只显示一个数字，改为允许叠加短暂显示。
- **预算**：每帧最多 1 个 T3/T4 爆发，其余间隔约 3 帧排队；中、低档粒子按 400/800、150/800 缩放。
- **降级顺序**（先砍）：环境光 → 拖尾 → 第三元素图案 → 粒子数 → 震屏/闪光 → 副元素图案。
- **永不降级**：血量阶段、保护核心、致死预告、伤害数字、护盾计数、防线警告、主元素形状。

## 5. 素材生产管线

### 5.1 现实情况

- 本会话无法直接调用 MiniMax。
- 本会话唯一的生图工具（Spline）按次扣用户点数，结果落在 Spline 场景里，不适合批量出素材。
- 仓库里现有的 `gen_*.py` 都是 PIL 程序化绘制，不调外部 API。

### 5.2 样张证据（2026-10-22）

`docs/design/concepts/pixel_density_compare_2026-10-22.png`：用临时调色板把现有的 1 格精英、Ignis 首帧、一个遗物图标按 A / B 两种精度自动像素化。

- **普通敌人、战斗 HUD 图标**：自动像素化后成了噪点团，轮廓读不出。
- **Boss**：有大块明暗，勉强可读。
- **原因**：现有素材是为高分辨率涂抹风画的，细节碎、明暗平。
- **结论**：路线 C 只能做过渡，用来统一精度；可读的像素素材**必须按像素规格重新出概念图**（平光、粗轮廓、大色块），再人工修整。

### 5.3 建议路线：A + C 混合

| 路线 | 做法 | 用在哪 |
|---|---|---|
| **C. 先像素化现有素材（过渡）** | 用新管线把现有敌人 / Boss / 图标原图自动缩到规格尺寸，套统一调色板、二值透明、自动描边 | 底座修好后**立刻**让全游戏统一精度，同时验证管线本身 |
| **A. MiniMax 概念图 → 像素化（正式）** | 我出统一提示词包（每个敌人 / 图标一条），用户在 MiniMax 批量生成，放进约定文件夹，脚本自动像素化并跑机检 | 按「造型 = 碰撞 = 机制」重画敌人；重画需要两个信息点的图标 |
| B. 代码里手写像素点阵 | 直接写 16×16 / 24×24 点阵 | 只用于极小件：钉、弹珠、弹丸、数字字体、状态标记 |

### 5.4 管线步骤（Python / PIL，可自动化）

- **生图约束**：
  - 固定正交 3/4 视角，平光，无投影、渐变、轮廓光。
  - 单一主体居中，占画面约 80%；纯色键控背景（不在调色板里）。
  - 粗轮廓，词条特征做成一个大形状，无文字。
  - 固定风格参考和种子。
- **缩小**：按面积平均缩到目标尺寸。不要从大图最近邻取样，那会取到噪点。
- **量化**：映射到项目固定调色板中最近的颜色（加权 RGB 距离）。32px 以下不抖动。
- **透明**：抠图蒙版按面积平均，覆盖率 ≥ 0.45 算实心，结果为二值透明。
- **描边**：自动生成，并留 1px 边。
- **机检**：
  - 像素全在调色板内、尺寸等于类别网格、透明只有 0/255、边缘无实心像素。
  - 轮廓填充率 0.6–0.9、出碰撞框 ≤ 1px。
  - 孤立像素报警。
  - 输出帧矩形清单和参数记录，同输入重跑结果逐字节一致。
- **必须人工**：眼睛 / 脸、词条可读性、锯齿与块面清理、动画帧。

## 6. UI 重构

### 6.1 原则

- **一套样式系统**：去掉 Tailwind CDN 和内联大样式块，统一成按组件拆分的 CSS + 设计令牌（颜色、间距、层级）。z-index 用固定的 5 层表：世界、HUD、面板、弹层、系统，不再出现 1–9999 的乱用。
- **不再用 JS 在侧栏之间搬 DOM**：手机 / PC 用 CSS 布局切换，同一份 DOM。
- **像素化 UI**：面板 9 宫格边框按 §2.2 规则做；正文长文本保留在 DOM，用清晰字体；数字和短标签用像素字体。
- **CRT 扫描线默认关闭**，保留为设置项。

### 6.2 按新循环重排的界面

| 阶段 | 必须一眼可见 | 去掉 |
|---|---|---|
| 挖掘 | 剩余发射（采集批 / 炼成弹珠）、桶倍率、热条、本次挖到的 ⚡ / 💎、下一波预告 | 0/15 充能、弹珠类型、符文发射器按钮 |
| 整备（新） | 余额、主炮 3 轨、设施位与冷却、道具位、挖矿升级、弹匣、下一波预告、「开战」 | — |
| 守卫 | 主炮剩余发数、设施冷却格、弹匣（可点替换下一发）、护盾、防线警告、波次胶囊 | SP 条、技能栏、技能编辑器、子弹属性卡 |
| 常驻顶栏 | 波次、⚡、💎、暂停 | 商人倒计时浮条（商人改为 Boss 后固定出现） |

元界面（主页、工坊、图鉴、试炼场）放在第二批，统一套用同一组件库。

## 7. 落地顺序（与核心循环阶段交织）
