# 符文系统重构设计方案

## 1. 现状分析
当前符文系统在游戏中作为局外成长（Meta Progression）存在，玩家通过商店升级或特定途径获取符文，但：
1. 符文掉落物 (`RuneLoot`) 虽在战斗中生成，但缺乏拾取逻辑。
2. 符文作为局外系统，与 Roguelike 游戏局内成长的核心体验（每局随机、逐步变强）脱节。
3. 未解决多余符文的冗余问题。

## 2. 重构目标
1. **游戏内系统化**：将符文系统完全移至局内，玩家在每局游戏中通过战斗掉落获取符文，并在局内构建 3x3 符文网格。
2. **回合成长机制**：随着回合数（Round）增加，符文掉落概率、稀有度或数量逐步提升，增强后期的 Build 深度。
3. **多余符文处理（熔炼系统）**：提供多余符文的消耗途径，例如将其转化为局内属性增益或特殊资源。

## 3. 详细设计

### 3.1 局内获取与掉落
*   **掉落逻辑**：保留 `loot_system.js` 中的智能掉落机制，但在 `combat_system.js` 中完善 `RuneLoot` 的拾取逻辑。
    *   **拾取方式**：战斗结束后自动拾取，或玩家通过鼠标悬停/点击拾取。
    *   **掉落概率随回合增长**：
        *   基础掉落率：例如 10%。
        *   回合加成：每经过 5 回合，掉落率增加 5%，上限 50%。
        *   代码修改位置：`combat_system.js` 的击杀逻辑中。

### 3.2 局内符文背包与网格
*   **生命周期**：`runeInventory` 和 `runeGrid` 在 `meta_startRun()` 或局内初始化时重置。
*   **UI 调整**：将符文发射器（Rune Launcher）的入口从 Meta 阶段（局外）移至 Selection 阶段（局内命运抉择）或战斗暂停面板。

### 3.3 多余符文处理：符文熔炼 (Rune Smelting)
由于 3x3 网格最多只能容纳 9 个符文，多余的符文会堆积在 `runeInventory` 中。
*   **机制**：在符文发射器 UI 中增加「熔炼」功能。
*   **操作**：玩家可以选择不需要的符文进行熔炼。
*   **收益**：熔炼符文可获得「符文碎片」或临时 Buff。
    *   方案 A（属性转化）：熔炼一个符文，永久提升当前局的某项基础属性（例如：伤害 +1%，或最大生命值 +5）。
    *   方案 B（重铸）：3 个不需要的符文可以重铸为 1 个随机的新符文。
*   **推荐采用方案 A + B 的结合**：
    *   提供一个「回收站」UI，拖入 3 个符文可重铸。
    *   或者简单的「分解」按钮，点击分解后获得 `rune_dust`（符文粉尘），消耗粉尘可以升级现有符文网格中的符文效果，或直接兑换局内金币/属性。
    *   **简化版实现**：在符文库存 UI 中，每个符文旁增加一个「分解」按钮，分解后直接转化为局内金币（Currency），用于在局内商店购买其他道具。

## 4. 实施步骤
1.  **修复拾取逻辑**：在 `phase_combat_update` 中遍历 `runeLootItems`，实现拾取并推入 `runeInventory`。
2.  **重置逻辑**：在 `sys_resetGame` 中清空 `runeInventory` 和 `runeGrid`。
3.  **UI 迁移**：将 `index.html` 中的符文发射器入口按钮移至局内界面（如 `phase-selection` 或 `phase-gathering`）。
4.  **掉落概率调整**：修改 `combat_system.js`，使掉落率与 `game.round` 挂钩。
5.  **多余符文处理 UI**：在 `ui_system.js` 的符文库存渲染中，为每个符文添加「分解」选项，分解获得局内资源。
