# Echo Alchemist Boss 系统设计方案

## 1. 设计概述
为了丰富《Echo Alchemist》的战斗体验，提升玩家构建符文套路的策略深度，我们设计了 8 个各具特色的 Boss。每个 Boss 均基于游戏现有的 7 种弹道属性和 7 种敌人词缀机制进行深度扩展。

**核心设计原则**：
- **无新增底层机制**：所有 Boss 行为均由现有系统（温度 temp、护盾 shieldCharges、词缀 affixes 等）组合或强化而来。
- **阶段性变化**：Boss 在生命值低于 50% 时将进入“狂暴阶段”（对应现有的 `berserk` 机制或温度机制），改变行为模式。
- **明确的克制关系**：每个 Boss 都有其对应的核心机制，玩家可以通过 `COUNTER_MAP` 中定义的属性克制关系（如火克护盾/再生，冰克极速/跳跃等）进行针对性打击。
- **符合世界观**：名称与设定紧扣“炼金”、“回声”、“元素”等主题。

## 2. Boss 详细设计

### 2.1 熔炉守卫·伊格尼斯 (Ignis, Warden of the Forge)
- **主题设定**：一台失控的炼金熔炉，不断为自身和周围的造物提供能量。
- **核心机制**：**超载护盾 (Shield) + 极速 (Haste)**
  - 拥有极高层数的物理护盾（`shieldCharges`），并且每回合行动两次（`haste`）。
  - **被动**：护盾存在期间，免疫温度异常（`temp` 无法积累）。
- **阶段变化**：
  - **普通阶段**：每回合行动两次，向下推进并尝试生成带有 `shield` 词缀的普通敌人。
  - **狂暴阶段（HP < 50%）**：护盾如果被击破，会进入 `berserk` 状态，温度（`temp`）急剧上升，每回合开始时会对周围格子造成火焰伤害（模拟熔炉爆炸）。
- **破绽谱**：**穿透 (Pierce) 与 火焰 (Pyro)**
  - 穿透属性可以直接无视护盾造成伤害，而火焰属性可以最快速度熔化护盾（对应 `COUNTER_MAP.pierce.shield = 1.0` 和 `COUNTER_MAP.pyro.shield = 1.0`）。
- **设计意图**：考验玩家的破盾能力，鼓励使用穿透或高频火焰攻击，避免被其高频行动压制。

### 2.2 霜晶缝合怪·格拉西斯 (Glacies, the Frost Amalgam)
- **主题设定**：由无数破碎的炼金冰晶缝合而成的巨兽，能够在战场上灵活跳跃并自我修复。
- **核心机制**：**跳跃 (Jump) + 再生 (Regen)**
  - 每回合能够跳跃多行（强化版 `jumpRows`），并在回合结束时恢复大量生命值（强化版 `regenPercent`）。
- **阶段变化**：
  - **普通阶段**：在战场上随机跳跃，避开玩家布置的密集弹幕区，同时缓慢回血。
  - **狂暴阶段（HP < 50%）**：跳跃频率翻倍（获得 `haste` 词缀），并且每次落地会冻结周围的钉子（Peg），使其暂时失效。
- **破绽谱**：**冰霜 (Cryo) 与 穿透 (Pierce)**
  - 冰霜属性的减速和冻结可以极大克制其跳跃能力（`COUNTER_MAP.cryo.jump = 0.8`），同时穿透属性也能有效打击跳跃中的目标（`COUNTER_MAP.pierce.jump = 0.8`）。
- **设计意图**：测试玩家的控制能力。如果不使用冰霜进行限制，它会在战场上乱跳并回满血量。

### 2.3 裂变母体·米克罗 (Mikro, the Fission Matriarch)
- **主题设定**：一个失败的炼金生命实验体，拥有无限增殖的能力，企图吞噬整个战场。
- **核心机制**：**分身 (Clone) + 治疗者 (Healer)**
  - 极高的分身触发概率（强化版 `cloneChanceHit` 和 `cloneChanceTurn`），并且能为所有分身提供高额治疗。
- **阶段变化**：
  - **普通阶段**：受击或回合开始时分裂出小型克隆体，并周期性释放治疗波（`healerRange` 扩大）。
  - **狂暴阶段（HP < 50%）**：母体不再移动，但分身概率达到 100%。每个存活的分身都会为母体提供微量减伤。
- **破绽谱**：**闪电 (Lightning) 与 散射 (Scatter)**
  - 闪电链可以完美克制密集的克隆体并打断治疗（`COUNTER_MAP.lightning.clone = 1.0`），散射也能进行大范围清场（`COUNTER_MAP.scatter.clone = 1.0`）。
- **设计意图**：考验玩家的群体伤害（AoE）能力，惩罚只注重单体爆发的构建。

### 2.4 贪婪之渊·噬神者 (The Devourer of Abyss)
- **主题设定**：炼金废料中诞生的深渊巨口，吞噬一切阻挡在它面前的实体。
- **核心机制**：**吞噬 (Devour) + 护盾 (Shield)**
  - 吞噬范围极大（强化版 `devourRange`），能够吞噬周围的普通敌人并获取它们的词缀和血量，同时自身带有基础护盾。
- **阶段变化**：
  - **普通阶段**：缓慢推进，优先吞噬路径上的其他敌人来强化自身。
  - **狂暴阶段（HP < 50%）**：消化不良导致其进入不稳定状态（`temp` 剧烈波动），吞噬动作变为全屏随机吸取，并获得被吞噬敌人的所有剩余护盾层数。
- **破绽谱**：**弹射 (Bounce) 与 激光 (Laser)**
  - 弹射可以将吞噬者弹开，打断其吞噬节奏（`COUNTER_MAP.bounce.devour = 0.8`）；激光则能精准打击并持续压制其吞噬行为（`COUNTER_MAP.laser.devour = 0.8`）。
- **设计意图**：时间管理测试。玩家必须在它吞噬太多敌人变得不可战胜之前，利用弹射或高能激光迅速将其击杀。

### 2.5 翠绿共生体·维里迪斯 (Viridis, the Emerald Symbiote)
- **主题设定**：被炼金药剂污染的远古植物，与战场环境形成了诡异的共生关系。
- **核心机制**：**再生 (Regen) + 治疗者 (Healer)**
  - 拥有游戏内最强的生命恢复能力。不仅自身每回合恢复巨量生命（强化版 `regenPercent`），还会将溢出的治疗量转化为周围普通敌人的临时生命值。
- **阶段变化**：
  - **普通阶段**：作为一个坚固的肉盾，持续为整个敌方阵线提供恢复。
  - **狂暴阶段（HP < 50%）**：放弃治疗其他敌人，将所有恢复能力集中于自身，并获得 `haste`（极速）词缀，加速逼近玩家底线。
- **破绽谱**：**激光 (Laser) 与 火焰 (Pyro)**
  - 激光的持续高频伤害可以完美压制再生效果（`COUNTER_MAP.laser.regen = 1.0`）；火焰的持续灼烧也能有效对抗高回复（`COUNTER_MAP.pyro.regen = 0.8`）。
- **设计意图**：持续伤害输出测试（DPS Check）。玩家需要构建出能够超越其恢复速度的持续伤害套路。

### 2.6 雷霆幻影·特斯拉 (Tesla, the Lightning Phantom)
- **主题设定**：纯粹由雷电能量构成的炼金幻象，速度极快且难以捉摸。
- **核心机制**：**极速 (Haste) + 分身 (Clone)**
  - 每回合行动三次（极端的 `haste`），并且在移动时会留下残影（带有低血量的 `clone`）。
- **阶段变化**：
  - **普通阶段**：高速在战场上穿梭，留下干扰玩家瞄准的残影。
  - **狂暴阶段（HP < 50%）**：本体隐藏在残影中，每次受到攻击都会与随机一个残影交换位置（利用现有的坐标互换逻辑）。
- **破绽谱**：**冰霜 (Cryo) 与 弹射 (Bounce)**
  - 冰霜是唯一能有效克制极速的属性，通过叠加冰冻层数（负 `temp`）使其减速甚至定身（`COUNTER_MAP.cryo.haste = 1.0`）；弹射则能在其分身之间快速弹跳，找出本体。
- **设计意图**：考验玩家的控制与追踪能力，鼓励使用冰霜属性进行控场。

### 2.7 混沌融合体·奇美拉 (Chimera, the Chaotic Amalgamation)
- **主题设定**：多种炼金元素强行融合的灾难产物，处于随时可能爆炸的不稳定状态。
- **核心机制**：**狂暴 (Berserk) + 吞噬 (Devour)**
  - 初始即带有高额的温度（`temp > 50`），处于半狂暴状态。能够吞噬周围的钉子（Peg）将其转化为自身的护盾。
- **阶段变化**：
  - **普通阶段**：一边吞噬钉子破坏玩家的弹射环境，一边因为高温度随机向周围释放火焰或冰霜冲击。
  - **狂暴阶段（HP < 50%）**：温度达到临界点（`temp > 100`），进入完全 `berserk` 状态。不再吞噬，但每次受击都有概率引发剧烈爆炸，对全场造成震荡。
- **破绽谱**：**穿透 (Pierce) 与 激光 (Laser)**
  - 穿透可以无视其吞噬钉子获得的护盾直接造成伤害；激光则能在不触发过多受击判定的情况下，稳定削减其血量。
- **设计意图**：环境破坏者。玩家需要权衡是尽快击杀它，还是保护战场上的关键钉子（特别是特殊槽位）。

### 2.8 永恒回声·奥罗波罗斯 (Ouroboros, the Eternal Echo)
- **主题设定**：代表炼金术终极循环的机械巨蛇，也是试炼的最终守门人。
- **核心机制**：**全词缀轮转 (Affix Rotation)**
  - 作为最终 Boss，它不固定拥有某种词缀，而是每 3 个回合在 [护盾+极速]、[再生+治疗]、[分身+跳跃] 之间轮转。
- **阶段变化**：
  - **普通阶段**：按照固定顺序轮转词缀，考验玩家符文网格的全面性。
  - **狂暴阶段（HP < 50%）**：轮转速度加快（每回合切换），并永久获得 `berserk` 词缀，温度持续上升，对玩家造成巨大的生存压力。
- **破绽谱**：**动态轮转**
  - 其破绽谱随当前词缀变化而变化。玩家需要利用符文网格系统（Rune Grid），在战斗中灵活调整（重铸或替换）主导属性，以应对其不断变化的形态。
- **设计意图**：终极综合测试。要求玩家不仅要有高伤害，还要深刻理解 `COUNTER_MAP` 的克制关系，并在局内动态调整策略。

## 3. 技术实现建议 (面向后续开发)
1. **实体扩展**：在 `entities.js` 中，扩展 `Enemy` 类的 `type === 'boss'` 逻辑，通过传入特定的 `affixes` 组合来实例化不同的 Boss。
2. **生成逻辑**：在 `spawn_system.js` 的导演系统（Director）中，新增 `spawn_spawnBoss(bossId)` 方法，在特定回合（如第 10、20、30 回合）强制生成对应的 Boss 实体。
3. **UI 提示**：Boss 出现时，调用现有的 `showToast` 或 `spawn_createFloatingText` 展示 Boss 名称，增强仪式感。
4. **阶段转换判定**：在 `takeDamage` 方法中检测 `this.hp / this.maxHp < 0.5`，若满足且未处于狂暴状态，则动态向 `this.affixes` 中推入 `berserk` 等词缀，并播放对应的特效（如 `particle` 爆发）。

## 4. Boss 移动间隔系统（已实现）

### 4.1 设计原则

Boss 不再每回合必定移动，而是根据其设定在常规模式下按固定间隔移动，狂暴模式下每回合必定移动。

| Boss | 常规移动间隔 | 狂暴移动间隔 | 设计意图 |
|------|------------|------------|----------|
| 熔炉守卫·伊格尼斯 | 2 回合 | 1 回合 | 有 haste 词缀，移动较频繁 |
| 霜晶缝合怪·格拉西斯 | 3 回合 | 1 回合 | 有 regen 词缀，移动较慢 |
| 裂变母体·米克罗 | 3 回合 | 1 回合 | 专注分裂，移动较慢 |
| 贪婪之渊·噬神者 | 2 回合 | 1 回合 | 吞噬后需要靠近 |
| 翠绿共生体·维里迪斯 | 3 回合 | 1 回合 | 专注治疗，移动缓慢 |
| 雷霆幻影·特斯拉 | 2 回合 | 1 回合 | 有 haste 词缀，移动较快 |
| 混沌融合体·奇美拉 | 2 回合 | 1 回合 | 混沌体，移动较频繁 |
| 永恒回声·奥罗波罗斯 | 3 回合 | 1 回合 | 永恒回声，移动最慢 |

### 4.2 技术实现

**配置层**：每个 Boss 在 `CONFIG.balance.bossConfigs[bossId]` 中新增 `moveInterval` 字段，表示常规模式下的移动间隔回合数。

**运行时状态**：每个 Boss 实体拥有两个运行时属性：
- `_moveInterval`：当前生效的移动间隔（从 `bossCfg.moveInterval` 初始化）
- `_moveCooldown`：当前剩余冷却回合数（0 = 本回合可移动）

**狂暴切换**：当 `berserked === true` 时，`_moveCooldown` 始终被重置为 0，实现每回合必定移动。

### 4.3 移动提示 UI

Boss 入场动画完成后，其底部下方会显示一个带有背景光晓的标签提示玩家本回合是否会移动：

| 状态 | 显示内容 | 颜色 |
|------|----------|------|
| 狂暴模式 | `⚡ 狂暴：每回合移动` | 橙红色（警告） |
| 本回合移动 | `➡ 本回合移动` | 红色（高度警告） |
| 下回合移动 | `⏳ 下回合移动` | 蓝色（提示） |
| N 回合后移动 | `⏳ N回合后移动` | 蓝色（提示） |

标签带有脉冲动画，在回合开始时预计算显示（`_willMoveThisTurn` 标志），玩家回合期间可以提前得知 Boss 下一次移动的时机。
