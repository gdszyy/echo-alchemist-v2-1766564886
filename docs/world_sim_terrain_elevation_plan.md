# World Sim Terrain Elevation Plan

> 范围：`src/world_sim/` 纯数据引擎。本文规划并记录“环形前缘”之后的地形高度扩展：地势如何影响生物迁徙、地幔演化与天气逻辑。

## 1. 目标边界

### 要达到的效果

1. 让“环形前缘”不只是晶石扩散形态，还能落在有地貌阻抗的世界上：外圈活跃、中心休眠的结构仍成立，但生物迁徙会被地势分割、延缓和导流。
2. 解决生物容易极化成“左右/上下对半开”的问题。迁徙者不能只按温度贪婪移动，还要考虑高原、盆地、山脊、窄颈这些现实地形因素。
3. 盆地要表现为“易守难攻”：盆地中心低，盆沿高，外来迁徙和竞争跨越盆沿时成本高，只有窄颈/山口能成为稳定通路。
4. 高原与平原之间要能自然形成“只有一个路径可走过去”的情况：高度差超过阈值时不可跨越，中等高度的山口/走廊才可通行。
5. 初始地势必须足够丰富：开局就要有高原、低地、山脊、盆地口袋、谷地/走廊等组合，确保生物部落从第一轮开始就会被地貌分化。
6. 地形必须由地幔层以地质时间尺度维护：高地幔能量和持久源井可以极慢地连续抬升局部地势，侵蚀让高度向邻域均值回落；默认 `terrainGeologyRate=0.01`，每步都变，但肉眼只在长时间跨度上累计明显变化。
7. 默认自然地形必须受 seed 驱动：固定 seed 可复现同一组山脊/盆地细节，不同 seed 应能产生可见差异。
8. 天气逻辑要读取地形：高海拔降温且削弱地幔热耦合，陡坡削弱热交换并增加地形抬升雷暴，盆地减少散热。
9. 晶石能量汲取不受地势影响：Alpha 能否吸地幔只看 `mantleEnergy`、源井和局部地幔能量差，不看 `terrainElevation`、坡度或盆地深度。

### 不要的效果

1. 不做真实 GIS 或完整水文/板块模拟。本阶段只引入高度、坡度、盆地深度、通行代价四个轻量字段。
2. 不把地形做成行政边界或硬编码阵营边界。地形只能改变成本、阈值和局部接触强度，不能直接指定物种势力范围。
3. 不让地形永久锁死全图。默认阈值允许中等坡度通行，只有陡崖才阻断；窄颈应成为可读的通路，而不是随机堵死。
4. 不接入 UI、Canvas、Game 主类或 EventBus。`world_sim` 继续保持纯数据引擎，视图层未来只能读取字段。
5. 不为了单个测试场景写死坐标。盆地、窄颈、源井都由播种器局部坐标生成，并可旋转、平移、调参。
6. 不让天气抢过地形主导权。本阶段天气只读地形并作一阶影响，不引入湿度、降雨、河流等新系统。
7. 不让地势高低改变晶石吸收效率，否则会把“地貌阻抗”和“晶石能源谜题”耦合成同一个系统。

## 2. 数据模型

地形字段统一从 `createCell()` 创建，避免各层临时给 `cell` 塞字段。

| 字段 | 范围 | 含义 |
|------|------|------|
| `terrainElevation` | `0..1` | 地势高度，越高越接近高原/山脊 |
| `terrainSlope` | `0..1` | 与邻格最大高度差，用于迁徙阻力和天气抬升 |
| `terrainBasinDepth` | `0..1` | 当前格低于周边平均高度的程度，用于盆地防守和热滞留 |
| `terrainMoveCost` | `>=1` | 根据坡度与盆地深度计算出的综合通行代价缓存 |

## 3. 跨层规则

### 地幔层

- 每步地幔更新后，将局部 `mantleEnergy` 映射为高度目标。
- 高能区通过 `terrainMantleUpliftRate * terrainGeologyRate` 极慢连续抬升。
- 邻域侵蚀通过 `terrainErosionRate * terrainGeologyRate` 让高度向邻居均值回落，同样每步连续发生。
- `mantleSourceStrength` 会额外抬升高度目标，让源井不仅是能量源，也是地貌高点。
- 地形扩张新生成的陆地继承邻域平均高度的 90%，避免凭空出现悬崖尖刺。

### 初始自然地形

- 初始高度由 `terrain_generator.js` 的多尺度 seed 噪声生成，而不是单一径向缓坡。
- 大尺度噪声负责高原/低地，区域噪声负责山丘起伏，ridge 噪声负责山脊，basin/valley 噪声负责盆地和谷地切割。
- 固定 seed 下地形完全复现，不同 seed 下高地、盆地和通路位置应明显不同。

### 地形识别检测器

- `terrain_detectors.js` 是纯读分析层，不写回 `grid`。
- 当前检测器包括 `highland`、`lowland`、`basin`、`ridge`、`valley`、`pass` 与兜底 `plain`。
- `engine.analyzeTerrainFeatures()` 返回各类计数与少量样本坐标，可供实验台、关卡生成、生物投放策略或调参测试读取。

### 程序化地形播种

- 源井格：高地势，强化“源头/高地”语义。
- 盆地格：中心低、盆沿高，天然形成防守边界。
- 窄颈格：中等高度，作为高原/盆地/平原之间的可通行山口。
- 圆形大陆：默认径向缓坡，便于继续验证环形前缘。

### 生物层

- 迁徙者单步只能跨越 `terrainMigrationMaxStep` 以内的高度差。
- 聚落直接扩张只能跨越 `terrainExpansionMaxStep` 以内的高度差。
- 可通行候选格再按“温度差 + 地形通行代价”评分。
- 异种竞争和同种协作按高度差削弱，盆地隔着高边缘时不会像平地那样强接触。

### 天气层

- `terrainElevationCooling` 让高海拔目标温度更低，低地相对更暖。
- `terrainMantleHeatDamping` 让地势越高，来自 `mantleEnergy` 的加热贡献越弱。
- 坡度通过 `terrainClimateSlopeResistance` 削弱热扩散和平流。
- 超过 `terrainClimateBarrierThreshold` 的坡差显著阻隔热交换。
- `terrainOrographicStormBoost` 让陡坡更容易触发地形抬升雷暴。
- `terrainBasinHeatRetention` 让盆地减少辐射散热。

### 晶石层

- Alpha 晶石吸收地幔能量只读取 `mantleEnergy`、`mantleSourceStrength`、`crystalMantleAbsorptionThreshold` 与 `crystalMantleLocalMargin`。
- `terrainElevation` / `terrainSlope` / `terrainBasinDepth` / `terrainMoveCost` 不得进入晶石吸能公式。

## 4. 验收

当前验证入口仍是：

```bash
node tests/validate_world_sim.mjs
```

新增验收点：

- 运行期所有存在地块的地形字段保持 finite。
- 地幔层会产生非零坡度和盆地深度。
- 同一 seed 的初始地形高度可复现，不同 seed 的初始地形高度有可测差异。
- 初始自然地形同时包含低地、中地和高地，海拔范围足够支撑多样部落分化。
- 地势高度每步都极慢连续变化，单步变化必须很小，但长跨度累计应可测。
- 地形检测器能在固定 seed 的初始自然地形中识别高原、低地、盆地、山脊、谷地和山口。
- 同等地幔能量下，高地与低地 Alpha 晶石吸收同样多的地幔能量。
- `seedCrystalSourceBasinTerrain()` 生成低盆底、高盆沿、中等高度窄颈。
- 迁徙者面对更理想温度的陡崖目标时，会选择唯一可通行的中坡走廊。
- 同等地幔能量下，高海拔格从地幔获得的升温幅度低于低海拔格。

## 5. 后续可扩展项

- 若要进一步处理天气，可在气候层新增湿度/降水字段，但必须先明确它们是否影响晶石或生物。
- 若要做河谷/山脉链条，应优先扩展 `terrain_features.js` 的播种器，而不是在生物层写特例。
- 若可视化层需要读取地形，只读 `cell.terrainElevation` / `terrainSlope` / `terrainBasinDepth`，不要让渲染层反写模拟状态。
