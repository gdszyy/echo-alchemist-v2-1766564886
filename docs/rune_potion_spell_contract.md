# 符文法术与药剂炼成收口规范

> 状态：2026-06-26 收口版，作为符文组合、药剂炼成、法阵形态与嵌套合法性的当前权威文档。
> 适用范围：`RUNE_DB`、`RUNEWORD_DB`、`POTION_SPELL_DB`、药剂炼成 UI、药剂战斗槽、法阵/形态/嵌套设计。
> 取代文档：旧 `rune_design_v5`、`rune_system_redesign`、`skill_system_alchemy_redesign`、风剑词条任务稿与根目录散落机制稿均已归档，不再作为实现依据。
> 落地计划：见 [`docs/potion_alchemy_development_plan.md`](potion_alchemy_development_plan.md)。
> 特效规格：具体法术表现、形态轮廓、粒子复用入口和分期实现见 [`docs/spell_vfx_design.md`](spell_vfx_design.md)。

## 1. 核心口径

```text
符文组合 = 法术内容
法阵 = 形态 + 嵌套合约
药剂 = 一个或多个符文法术按法阵与嵌套规则封装后的可释放结果
```

符文组合回答“发生什么”。

法阵回答“它以什么形态出现、什么时候结算、是否允许嵌套”。

合法性规则回答“这个组合有没有足够视觉回报和战术意义”。

## 2. 药剂炼成顺序

药剂炼成不是一次性“符文 -> 法阵 -> 药剂”的线性流程，而是一个可继续搭建的工作台草稿态。玩家可以先做出一个可用法术，绘制法阵决定形态与嵌套形式，然后选择立刻封装成药剂，或继续投入符文配置下一个法术并尝试嵌套。

| 步骤 | 名称 | 规则 |
|---:|---|---|
| 1 | 投入符文 | 玩家向炼金台投入多个符文，投入即实打实消耗，不能撤回。 |
| 2 | 解析符文法术 | 如果当前符文组能组成法术，内部生成一个 `spellContent`；如果不能组成法术，本次结构不可继续，按失败炼成处理。玩家只能知道“可以生成/不可生成”，不知道具体会生成什么。 |
| 3 | 绘制法阵 | 玩家绘制法阵。法阵决定该法术的形态与嵌套形式，例如 Orb、药瓶、Beam、坠击、防御塔 active/death。 |
| 4 | 校验当前节点 | 使用第 5 节矩阵校验 `法阵 x 法术内容`。非法组合不能靠降低数值放行。 |
| 5A | 手动接触封装 | 玩家手动接触/确认炼成时，将当前草稿封装为药剂，随后计算品质与装药量并写入药剂槽。 |
| 5B | 继续投入符文 | 玩家不封装，而是继续投入新的符文配置下一个法术。新投入符文同样立即消耗。新符文组必须先能组成法术。 |
| 6B | 复合法术嵌套校验 | 新法术必须同时满足自身 `法阵 x 法术内容` 合法性，以及“当前草稿节点 x 新法术节点”的复合法术嵌套规则。这个组合必须能从嵌套表查到，查不到即不允许嵌套。 |
| 7B | 接入草稿 | 嵌套合法后，新节点接入当前草稿；玩家再次选择手动接触封装，或继续投入符文配置下一层。 |

手动接触是“封装药剂”的仪式动作，不是额外法术触发。只有手动接触后，草稿才会从炼金台结构变成 `preparedPotionSpell`。

所有投入符文都在投入瞬间消耗。炼金台只反馈结构状态：可继续、可封装、不可生成；最终封装前不展示具体药剂名、具体效果、品质或装药量。失败炼成的返还比例继续使用 `CONFIG.gameplay.potionAlchemyFailRefundRatio`，当前默认 0.35。

## 2.1 信息可见性与风险规则

| 阶段 | 玩家能知道 | 玩家不能知道 |
|---|---|---|
| 投入符文后 | 当前符文组是否能组成法术 | 具体法术名称、具体效果、最终药剂名 |
| 绘制法阵后 | 当前法阵是否能承载该法术 | 具体形态参数、最终伤害/状态数值 |
| 继续嵌套后 | 当前复合结构是否仍合法 | 最终复合法术的实际结算细节 |
| 手动接触前 | 是否可以封装成药剂 | 最终生成的药剂是什么、品质多少、装药量多少 |
| 手动接触后 | 最终药剂名、效果、品质、装药量 | 无 |

UI 文案应表达为“结构稳定，可以封装”“结构仍可继续嵌套”“结构坍塌，炼成失败”，而不是提前显示“将生成某某药剂”。

## 2.2 详细炼成流程

炼成流程分为 6 个阶段：空台、投料、成法、绘阵、嵌套、封装。

| 阶段 | 触发 | 系统动作 | 玩家反馈 | 下一步 |
|---|---|---|---|---|
| 空台 | 玩家进入药剂炼成 | 初始化本次 `alchemyDraft`，没有节点，没有待解析符文组 | 显示空炼金台、可投入符文 | 投入符文 |
| 投料 | 玩家投入符文 | 符文立即从库存扣除，写入本次炼成消耗账本 `consumedRunes` | 显示符文已入炉，不显示结果 | 达到最低组合法术数量后解析 |
| 成法 | 当前投料组可解析 | 内部生成一个隐藏 `spellContent` 节点 | 只显示“结构有反应 / 可以绘制法阵” | 绘制法阵 |
| 绘阵 | 玩家绘制法阵 | 根据法阵识别 `formId`、`nestingMode`、`slotType`，校验 `法阵 x 法术内容` | 只显示“法阵稳定 / 法阵排斥” | 手动接触封装或继续嵌套 |
| 嵌套 | 玩家继续投入符文 | 新符文立即消耗，内部解析第二个隐藏 `spellContent`，再查复合法术嵌套规则 | 只显示“复合结构稳定 / 结构坍塌” | 接入草稿、继续嵌套或失败 |
| 封装 | 玩家手动接触炼金结构 | 结束草稿态，计算最终药剂、品质、装药量，写入 `preparedPotionSpell` | 此时才显示药剂名、效果、品质、装药量 | 关闭炼成或开始新炼成 |

最低组合法术数量由配方系统定义。当前建议默认 3 枚符文形成一个法术节点，但后续可以允许特殊遗物、特殊法阵或高阶配方改变该数量。

## 2.3 投料消耗账本

投料即消耗，因此炼成过程必须维护本次消耗账本。

```js
alchemyDraft = {
    draftId: 'alchemy_draft_001',
    state: 'empty' | 'feeding' | 'spell_ready' | 'form_ready' | 'nesting' | 'sealed' | 'failed',
    consumedRunes: [
        { id: 'rune_pyro_1', level: 1, sourceSlot: 'inventory', consumedAtStep: 1 }
    ],
    pendingRuneGroup: [],
    root: null,
    failureReason: null
}
```

消耗账本规则：

| 规则 | 说明 |
|---|---|
| 投入即扣除 | 玩家把符文放进炼金台时，立即从 `runeInventory` 移除。 |
| 不支持撤回 | 已投入符文不能拖回库存，避免免费试错。 |
| 草稿失败不返符文 | 失败只按失败返还规则返还局内货币，不返还原符文。 |
| 封装成功不额外扣除 | 所有成本已在投料阶段支付，封装只结算结果。 |
| 覆盖旧药剂不返还 | 如果已有旧药剂，开始新炼成或最终封装时按现有覆盖规则弃置旧药剂，不返还旧装药量。 |

## 2.4 法术节点生成

每次投入一组符文后，系统内部尝试生成一个法术节点。

```text
符文组 -> 是否命中符文法术公式 -> 隐藏 spellContent -> 等待玩家绘制法阵
```

玩家只知道该组符文是否“能成法”，不知道命中的是哪个 `runewordId` 或 `spellType`。

节点内部结构：

```js
{
    nodeId: 'node_1',
    hiddenSpellContentId: 'runeword_meltdown',
    hiddenSpellType: 'burst',
    formId: null,
    nestingMode: null,
    slotType: null,
    sourceRuneIndexes: [0, 1, 2],
    children: []
}
```

字段命名中的 `hidden` 表示该字段可供系统校验与最终封装使用，但不能在封装前直接展示给玩家。

## 2.5 法阵绘制与合法性

玩家绘制法阵后，系统识别该法阵对应的形态与嵌套模式。

```text
玩家绘制法阵 -> 识别 formId/nestingMode/slotType -> 校验 法阵 x 隐藏法术内容
```

法阵校验结果只分三类：

| 结果 | 含义 | UI 反馈 |
|---|---|---|
| `stable` | 当前法术可以被该法阵承载 | 结构稳定，可以封装 |
| `extendable` | 当前法术可以被承载，并且允许继续嵌套 | 结构稳定，可以继续投入 |
| `rejected` | 当前法术不能被该法阵承载 | 法阵排斥，结构坍塌 |

`rejected` 进入失败炼成。失败时本轮已投入符文不返还。

## 2.6 继续嵌套流程

继续嵌套不是“再加一个效果”，而是重新经历一轮投料与绘阵，再把新节点接入旧节点。

```text
已有稳定节点
-> 玩家继续投入符文
-> 新符文立即消耗
-> 新符文组内部解析成隐藏法术
-> 玩家为新法术绘制法阵
-> 校验新节点自身合法性
-> 查表校验 父节点 x 子节点 的复合法术嵌套规则
-> 合法则接入，非法则结构坍塌
```

复合嵌套必须命中明确规则，不能用相近类型猜测。

| 校验层级 | 例子 | 失败处理 |
|---|---|---|
| 子节点自身合法性 | `Beam x 状态` 合法，`Beam x Orb` 非法 | 结构坍塌 |
| 父子嵌套合法性 | `Orb 破裂 -> 状态` 可查表，`Orb -> Orb` 查表禁用 | 结构坍塌 |
| 互斥槽位合法性 | 防御塔 `active` 与 `death` 不能同时存在 | 结构坍塌 |
| 禁用类型合法性 | 纯扣血、链式反应、吸取/链接不进入嵌套 | 结构坍塌 |

嵌套失败时，已经投入的新符文和旧草稿消耗都不返还。是否允许保留旧稳定草稿需要单独定规则；当前建议不保留，失败即整炉坍塌，这样风险清晰。

## 2.7 手动接触封装

手动接触是炼成的封口动作。

```text
玩家手动接触稳定炼金结构
-> 系统锁定草稿树
-> 计算最终药剂
-> 计算品质与装药量
-> 写入 preparedPotionSpell
-> 显示最终结果
```

封装规则：

| 规则 | 说明 |
|---|---|
| 只有稳定结构可封装 | `stable` 或 `extendable` 状态可以封装，`feeding` / `rejected` / `failed` 不可封装。 |
| 封装后才揭示结果 | 药剂名、图标、效果、品质、装药量只在封装后出现。 |
| 封装消耗整棵草稿树 | 一次封装生成一瓶药剂，草稿树清空。 |
| 旧药剂按覆盖规则处理 | 若已有 `preparedPotionSpell`，新药剂写入前弃置旧药剂。 |

## 2.8 失败与中断处理

| 场景 | 处理 |
|---|---|
| 投入符文不足以形成法术 | 保持 `feeding`，允许继续投入；若玩家主动终止，则失败炼成。 |
| 当前符文组明确不能形成法术 | 进入 `failed`，本轮符文不返还。 |
| 法阵排斥当前法术 | 进入 `failed`，本轮符文不返还。 |
| 复合嵌套查表失败 | 进入 `failed`，整炉坍塌，本轮符文不返还。 |
| 玩家关闭炼金台 | 如果已有消耗但未封装，视为中断失败；需要二次确认。 |
| 玩家进入战斗 | 如果已有消耗但未封装，视为中断失败；需要二次确认或禁止进入战斗。 |
| 刷新/存档恢复 | 已消耗符文与草稿态必须可恢复，避免投料后刷新套利。 |

中断确认文案必须明确：“已投入符文不会返还”。

## 2.9 UI 状态建议

| 内部状态 | UI 文案 | 按钮 |
|---|---|---|
| `empty` | 药匣空置，等待投料 | 投入符文 |
| `feeding` | 炉内尚未成法，可继续投料 | 继续投料 / 放弃炼成 |
| `spell_ready` | 炉内有反应，请绘制法阵 | 绘制法阵 |
| `form_ready` | 结构稳定，可以封装或继续投入 | 手动接触封装 / 继续投料 |
| `nesting` | 复合结构校验中 | 暂不可封装 |
| `sealed` | 药剂已生成 | 查看药剂 / 关闭 |
| `failed` | 结构坍塌，炼成失败 | 领取返还 / 重新开始 |

禁止在 `spell_ready`、`form_ready`、`nesting` 阶段显示具体药剂预览。

## 2.10 涉及流程总览

药剂炼成相关流程分为局外入口、炼成主流程、嵌套分支、失败中断、战斗使用、记录回看六类。

| 流程 | 入口 | 结束 | 涉及页面/层 | 关键规则 |
|---|---|---|---|---|
| 解锁流程 | 获得贤者药匣 | 炼金台显示药剂炼成入口 | 遗物获得提示、炼金台入口 | 只解锁入口，不强制弹出炼成。 |
| 基础炼成 | 药剂炼成 Tab 投入符文 | 手动接触封装成功 | 药剂炼成 Tab、符文投料区、法阵绘制区、封装结果层 | 投料即消耗，封装前只显示稳定性。 |
| 继续嵌套 | 稳定结构选择继续投料 | 新节点接入或整炉失败 | 药剂炼成 Tab、嵌套结构视图、法阵绘制区 | 新符文组与父子嵌套都必须查表合法。 |
| 失败/中断 | 结构坍塌、关闭炼金台、进入战斗 | 领取失败返还或确认放弃 | 失败结果层、中断确认层 | 已投入符文不返还，只返局内货币。 |
| 覆盖旧药剂 | 已有药剂时开始新炼成或封装新药剂 | 旧药剂弃置，新药剂写入 | 当前药剂条、覆盖确认层、封装结果层 | 旧装药量不返还。 |
| 战斗使用 | 点击战斗 HUD 药剂槽 | 装药量 -1 或药剂耗尽 | 战斗 HUD 药剂槽、药剂释放反馈 | 药剂无 SP、无冷却，只消耗装药量。 |
| 记录回看 | 封装成功后 | 图鉴/历史记录更新 | 炼金笔记、真理之书可选入口 | 只记录已揭示药剂，不记录失败黑箱细节。 |

| 当前药剂条 | 页面组件 | 已有 `preparedPotionSpell` | 药剂图标、装药量、弃置/覆盖风险提示 | 未封装草稿结果。 |
| 战斗药剂槽 | HUD 组件 | 战斗阶段 | 药剂图标、装药量、空瓶状态、释放按钮 | SP 消耗、冷却遮罩。 |
| 炼金笔记 | 图鉴/记录 | 至少封装成功过一次 | 已揭示药剂、效果说明、装药范围、使用记录 | 未揭示药剂完整配方。 |

## 2.12 页面设计方案

整体视觉方向应区别于普通符文配置页：符文配置是“理性排布”，药剂炼成是“危险实验”。药剂炼成页要有更强的仪式感、不可逆感和黑箱感。

| 页面/层 | 布局设计 | 视觉重点 | 交互重点 |
|---|---|---|---|
| 药剂炼成 Tab | 中央为圆形炼金炉/法阵画布，左侧为符文库存，右侧为结构状态与操作按钮 | 暗金金属炉框、玻璃药匣、液体光、烟雾与刻痕 | 投料拖入炉心，绘阵在中央完成。 |
| 符文投料区 | 已投入符文围绕炉心成为外环残影 | 符文碎裂成粉、进入炉液后留下元素色残光 | 投入后不可撤回，用动画强调消耗。 |
| 法阵绘制区 | 炉心上方覆盖可绘制圆盘，绘制后吸附成标准法阵 | 稳定时线条收束发光，排斥时线条断裂逆流 | 玩家画的是形态契约，不是选菜单。 |
| 嵌套结构视图 | 使用抽象节点树或纵向试管结构表现层级 | 节点只显示“稳定核心/未知子核”，不显示具体法术 | 让玩家知道层数与风险，不知道答案。 |
| 手动接触封装层 | 中央出现发光药匣和触碰热区 | 手掌烙印、玻璃凝结、药液定色 | 触碰是最终确认，不提前揭示结果。 |
| 封装结果层 | 药剂卡片从炉中升起，显示最终信息 | 药瓶图标、药液颜色、品质框、装药量刻度 | 显示“装入药匣”，如果覆盖旧药剂说明旧药剂已弃置。 |
| 失败坍塌层 | 法阵碎裂，炉液变暗，符文灰烬沉底 | 黑烟、裂纹、暗红警示光、少量返还货币飞出 | 强调失败有代价，但有最低补偿。 |
| 战斗药剂槽 | 固定在普通技能旁，但视觉上独立成药瓶槽 | 药液液面遮罩、空瓶裂纹、最后一发闪烁 | 显示 `charges/maxCharges`，不显示 SP。 |
| 炼金笔记 | 像炼金日志，按已揭示药剂归档 | 手写标签、封蜡、药剂小样、失败页烧痕 | 只复盘已生成，不泄露未发现配方。 |

## 2.13 美术资产设计方案

资产优先做可复用组件，不为每种药剂单独画完整大图。第一批资产应服务“投料、绘阵、稳定、坍塌、封装、战斗槽”六个核心状态。

| 资产 | 建议规格 | 用途 | 设计要求 |
|---|---|---|---|
| 炼金炉底座 | 512x512 PNG 或 9-slice 面板 | 药剂炼成 Tab 中央主视觉 | 暗金金属、玻璃管、刻蚀槽、可承载多层发光叠加。 |
| 法阵画布底纹 | 512x512 透明 PNG | 法阵绘制区底层 | 低对比刻线，避免干扰玩家绘制轨迹。 |
| 法阵稳定线 | SVG 或 Canvas 程序线条 | 绘阵成功反馈 | 亮金/元素色收束，线条干净，不能像普通 UI 边框。 |

## 3. 法术内容类型

| 类型 | 是否保留 | 可否作为嵌套子法术 | 说明 |
|---|---:|---:|---|

## 4. 法阵形态与触发语义

具体 VFX 轮廓、三段式表现与性能预算口径见 [`spell_vfx_design.md`](spell_vfx_design.md)。本节只定义形态合法性与触发语义。

| 法阵 | 定位 | 显性结算语义 | 允许内容 | 禁止内容 |
|---|---|---|---|---|
| Orb | 移动容器 | 破裂释放 | 爆发、状态、延迟、构筑 | Orb/普通弹体、Beam、纯扣血 |
| 药瓶 | 抛掷容器 | 碎裂释放 | 爆发、状态、延迟、构筑 | 纯扣血、复杂弹体套娃 |
| 地雷 | 布设物 | 引爆释放 | 爆发、状态、延迟、构筑 | 纯扣血、普通弹体、塔生塔 |
| Beam | 传导形态 | 命中传导 | 状态、延迟 | tick 触发、结束触发、生成 Orb |
| 回旋 | 轨迹形态 | 掠过/覆盖 | 状态词条、少量延迟 | 回终点触发、复杂嵌套 |
| 斩击 | 瞬发切割 | 斩击结算 | 状态、延迟、轻量爆发 | 复杂嵌套、纯扣血子法术 |
| 坠击 | 指定敌人打击 | 目标点结算 | 爆发、状态、延迟、构筑 | 坠击再坠击、Orb、链式反应 |
| 扫射激光 | Beam + 回旋复合 | 沿路径传导 | 状态、延迟 | 生成弹体、隐藏扣血 |
| 防御塔 | 构筑载体 | 回合开始或死亡释放 | 爆发、状态、延迟、坠击 | active+death 双槽、塔生塔 |

工程事件可以存在于底层，但不直接暴露给玩家。比如 Orb 的命中、超时、被摧毁统一叫“破裂”；Beam 的逐帧结算统一叫“传导”。

## 6. 明确禁用清单

| 组合 | 处理 | 原因 |
|---|---|---|
| Orb 嵌套 Orb | 禁止 | 碰撞后再发 Orb 几乎没有视觉回报。 |
| Orb 嵌套普通弹体 | 禁止 | 像隐藏追加伤害。 |
| Beam 命中生成 Orb | 禁止 | 读不清，像机关枪触发器。 |
| Beam tick 触发扣血 | 禁止 | 工程事件，不是法术。 |
| 回旋终点触发法术 | 禁止 | 工程感强。 |
| 防御塔生成防御塔 | 禁止 | 塔生塔会套娃。 |
| 爆发嵌套爆发连锁 | 禁止 | 本版不做链式反应。 |
| 纯扣血作为子法术 | 禁止 | 折叠成父法术数值。 |
| active 与 death 同时存在 | 禁止 | 防御塔只能选择一种嵌套模式。 |

## 7. 防御塔/构筑收口规则

构筑/地形类统一收口为防御塔类构筑实体，不另做地形系统。

```text
防御塔 = 可承伤、可阻挡、可死亡、可在一个互斥槽位中承载法术的构筑载体
```

| 项 | 规则 |
|---|---|
| 血量 | `当前回合数 * 基础血量系数 * 符文血量倍率`。 |
| 承伤 | 敌人撞击时复用敌人撞击护盾的伤害计算逻辑。 |
| 嵌套槽 | `active` 或 `death` 二选一。 |
| active | 回合开始时，从防御塔位置释放一次嵌套法术。 |
| death | 防御塔死亡时，从防御塔位置释放一次嵌套法术。 |
| 释放方式 | 由嵌套法术自己决定，防御塔不提供额外索敌/冷却/发射 AI。 |
| 回响 | 只提供防御塔血量加成，不允许提供第二槽或复制施法。 |

防御塔不负责射程、冷却、自动索敌、双槽触发、塔生塔。它只提供“站位 + 承伤 + 互斥触发时机”。

## 8. 坠击/迫击收口规则

坠击用于替代“Orb 生 Orb”这类看不清的产出嵌套。

```text
坠击 = 指定敌人 -> 播放飞行/坠落动画 -> 中途不参与碰撞 -> 到达目标点结算携带法术
```

允许携带爆发、状态、延迟、构筑/防御塔。

禁止坠击再坠击、Orb、普通弹体、链式反应、纯扣血子法术。

## 9. Beam + 回旋收口规则

Beam 与回旋不互相嵌套，而是合成一个复合形态：扫射激光。

```text
扫射激光 = Beam 的传导结算 + 回旋/摆扫轨迹
```

扫射激光只允许状态与延迟结算，不允许生成 Orb、生成普通弹体、隐藏扣血或链式反应。

| `runeword_kinetic_decay` | 动能衰变 | 弹跃 + 穿刺 + 弹跃 | 命中后伤害衰减 | 可迁移为状态/延迟结算；纯数值部分折叠。 |
| `runeword_echo_shot` | 回响射击 | 散裂 + 弹跃 + 散裂 | 命中产出子弹 | 药剂嵌套禁用；不要作为 Orb/弹体产出。 |
| `runeword_son_sword_summon` | 召剑之语 | 破甲 + 穿刺 + 弹跃 | 命中召子飞剑 | 只在有清晰飞剑演出时保留为专门召唤，不作为普通嵌套。 |
| `runeword_bullet_to_sword` | 化弹为剑 | 穿刺 + 弹跃 + 穿刺 | 弹体替换为飞剑 | 作为形态替换处理，不作为嵌套子法术。 |

## 11. 药剂草稿与结果字段建议

药剂在炼金台中应先表现为草稿树。每个节点都保留“符文法术内容”和“法阵形态”两部分，但这些字段属于内部解析结果；最终封装前，UI 只能展示稳定性与可继续性，不展示具体 `spellContentId`、`spellType` 或最终药剂结果。嵌套边必须记录命中的复合法术嵌套规则。

```js
{
    draftId: 'alchemy_draft_001',
    root: {
        nodeId: 'node_1',
        spellContentId: 'runeword_meltdown',
        spellType: 'burst',
        formId: 'orb',
        nestingMode: 'rupture',
        slotType: null,
        sourceRunes: [
            { id: 'rune_pyro_1', level: 1 },
            { id: 'rune_pyro_2', level: 1 },
            { id: 'rune_pyro_1', level: 1 }
        ],
        children: [
            {
                nodeId: 'node_2',
                attachRuleId: 'orb_rupture_allows_status',
                spellContentId: 'runeword_absolute_zero',
                spellType: 'status',
                formId: 'bottle',
                nestingMode: 'shatter',
                slotType: null,
                sourceRunes: [
                    { id: 'rune_cryo_1', level: 1 },
                    { id: 'rune_cryo_2', level: 1 },
                    { id: 'rune_cryo_1', level: 1 }
                ],
                children: []
            }
        ]
    }
}
```

玩家手动接触封装后，草稿被拍平成可释放药剂结果：

```js
{
    potionId: 'potion_pyro_orb_meltdown',
    draftId: 'alchemy_draft_001',
    rootNodeId: 'node_1',
    quality: 1,
    charges: 2,
    maxCharges: 3,
    spellTree: { /* 来自炼金台草稿树 */ }
}
```

当前静态 `POTION_SPELL_DB` 仍是首版可释放药剂清单，但每个条目必须显式声明 `spellType`、`formId`、`nestingMode` 与 `vfxProfile`。战斗层只在释放后读取这些字段用于视觉表现：`formId: 'bottle'` 表示药瓶容器，`nestingMode: 'shatter'` 表示碎裂释放，`vfxProfile` 只描述目标点、碎裂样式、残影粒子与语义标签，不参与伤害或状态计算。`vfxProfile.shatterStyle` 现在会驱动具体碎裂图案：雾化铺场、爆破、标记电弧、碎片法印、坍缩内收、弹药封装或过载裂解。

```js
        { id: 'rune_cryo_1', level: 1 },
        { id: 'rune_bounce_1', level: 1 },

    ],

```

## 12. 后续实现优先级

| 优先级 | 内容 | 原因 |
|---:|---|---|
| P0 | 药剂合成解析顺序改为“投入符文即消耗 -> 内部判定是否成法术 -> 玩家绘制法阵 -> 手动接触封装或继续投入符文嵌套” | 避免把炼成误写成免费预览或一次性线性流程。 |
| P0 | 在 `POTION_SPELL_DB` 中拆分 `spellType`、`formId`、`nestingMode`、`vfxProfile` | 已在静态药剂库和战斗释放表现层落地；后续炼金台草稿树也要复用同一字段。 |
| P0 | 禁用 Orb 生 Orb、Beam 生 Orb、纯扣血嵌套 | 先封住最容易变隐藏伤害的入口。 |
| P1 | 防御塔 active/death 互斥槽 | 构筑类玩法的稳定基础。 |
| P1 | 坠击/迫击法阵 | 替代产出类 Orb 嵌套。 |
| P1 | 扫射激光复合形态 | 承接 Beam + 回旋幻想。 |
| P2 | 旧 `RUNEWORD_DB` 分类迁移 | 保留旧词条表现，同时逐步对齐新法术类型。 |
