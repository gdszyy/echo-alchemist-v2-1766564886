# 敌人视觉设计 V2：尺寸基底、专属词条与 3×3 敌人类型规范

## 1. 设计目标与当前实现依据

本文档用于接续既有敌人视觉重设计工作，将敌人从“单格方块 + 任意词条”的松散表达，推进为“**尺寸足迹决定基底形体，基底形体绑定少量专属词条，通用词条作为附加层叠加**”的规范体系。这样做的核心目的，是让玩家在看到敌人轮廓、占格大小和底层材质时，就能初步判断其战术职责，而不是必须阅读词条图标或等待行为触发后才能理解威胁。

当前实现已经具备支撑该体系的基础。普通敌人按 `enemyWidth × enemyHeight` 的单格网格生成，带词条的敌人会被标记为 `type='elite'`。重装变种已经以 `3×1` 宽体敌人的形式存在，生成时设置 `affixes=['heavyArmor']`、`type='elite'`、`isWideEnemy=true`。Boss 则采用固定 `3×2` 尺寸，并且根据 `bossType` 设置 `polygon`、`arc` 或 `aabb` 等碰撞形状。与此同时，`spawn_applyMinionShape(e)` 已经可以根据最近击败或出现过的 Boss 类型，为随从分配异形几何形状，这说明当前系统已经不再只能表达矩形敌人。[`src/spawn_system.js`](../src/spawn_system.js)

> **核心结论**：V2 不应该把所有敌人继续视为同一种方块容器。敌人应拆为三层语义：第一层是占格尺寸，第二层是基底类型，第三层才是词条。尺寸与基底类型共同决定“它是什么”，词条决定“它额外会什么”。

## 2. 术语与层级边界

为了避免继续混淆 `type`、`affixes`、Boss 类型与视觉形体，本文档将敌人语义拆为四个层级。这里的命名并不要求立即成为代码字段，但后续实现应尽量朝这个方向收敛。

| 层级 | 建议字段 | 说明 | 示例 |
|---|---|---|---|
| **等级层** | `type` | 控制普通、精英、Boss 的基础底色、边框、光晕和血量展示强度。 | `normal`、`elite`、`boss` |
| **尺寸层** | `footprint` | 控制敌人占用几列几行，是最优先的视觉识别信号。 | `1x1`、`2x2`、`3x1`、`3x3` |
| **基底层** | `baseArchetype` | 控制敌人的主体轮廓、材质语言、默认行为倾向和专属词条。 | `maw`、`bastion`、`echo_spire` |
| **词条层** | `affixes` | 控制可叠加机制。分为通用词条和基底专属词条。 | `shield`、`regen`、`devour`、`heavyArmor` |

其中，**通用词条**可以附加在多数敌人身上，只提供外部光环、内部纹理或行为加成，不应该改变敌人的基础尺寸。当前除 `heavyArmor` 与 `devour` 以外的既有词条，建议都归入通用词条池，包括 `shield`、`regen`、`healer`、`haste`、`jump`、`clone` 与 `berserk`。这些词条可以继续由导演系统、普通词条权重或 Boss 影响来分配。[`src/config.js`](../src/config.js)

| 词条类别 | 词条 | 设计定位 | 是否决定尺寸 |
|---|---|---|---|
| **通用词条** | `shield`、`regen`、`healer`、`haste`、`jump`、`clone`、`berserk` | 为既有敌人追加机制和视觉特效，可出现在多种尺寸上。 | 否 |
| **基底专属词条** | `heavyArmor`、`devour` | 直接定义敌人身体结构和战斗职责，应与特定基底尺寸绑定。 | 是 |
| **新增专属词条** | `deflectionWard`、`echoRelay`、`prism`、`hive`、`siege`、`gravityWell`、`siphon` | 用于扩展 3×3 范围内的新敌人类型，不进入普通通用词条池。 | 是 |

## 3. 基底敌人的统一规则

基底敌人应当遵循“**先读尺寸，再读轮廓，最后读词条特效**”的视觉顺序。尺寸越大，敌人越不应依赖外部光环来表达强度，而应通过身体内部的结构、材质和负空间直接呈现威胁。例如，吞噬敌人默认应是 `2×2`，因为它的机制是吸收周边单位并继承资源；如果仍然保持 `1×1`，玩家很难从画面上理解它为什么拥有比普通敌人更强的成长能力。

| 规则 | 规范说明 | 视觉原因 | 实现建议 |
|---|---|---|---|
| **尺寸绑定职责** | 每一种非通用核心职责都必须有默认尺寸。 | 玩家可以通过占格面积预判威胁级别。 | `baseArchetype` 默认生成 `footprint`。 |
| **专属词条绑定基底** | `devour`、`heavyArmor` 这类词条不再随机附给任意单格敌人。 | 避免“单格小怪突然拥有大型怪机制”的认知落差。 | 生成时先选择基底，再注入专属词条。 |
| **通用词条不改尺寸** | `shield`、`regen`、`haste` 等只作为叠加层。 | 保持词条系统灵活，同时不破坏形体语义。 | 沿用 Layer 3.5 / Layer 8 的词条特效。 |
| **大体型少词条** | `2×2` 以上敌人默认只带 1 个专属词条，最多追加 1 个通用词条。 | 防止视觉噪声和机制过载。 | 生成权重中限制大型敌人的随机词条数。 |
| **轮廓优先于颜色** | 不同基底必须有不同外轮廓或内部主结构。 | 色彩会被温度、护盾、精英边框覆盖。 | 使用 polygon/arc/aabb 与预计算纹理。 |

## 4. 既有基底的重新定义

### 4.1 标准敌人：`1×1` 炼金残渣

标准敌人仍然是当前网格系统的基础单位。它的职责是提供密度、弹射目标、穿透路径和通用词条载体。其默认基底不绑定任何专属词条，只通过 `type` 和通用词条表现变化。视觉上应保持低复杂度，以暗色炼金金属、矿石斑点或微弱能量流线作为底层纹理，避免抢占大型敌人的视觉权重。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `1×1` |
| 默认词条 | 无 |
| 可叠加词条 | 所有通用词条 |
| 轮廓语言 | 圆角矩形或轻微切角矩形 |
| 主要用途 | 基础压力、阵型填充、通用机制教学 |

### 4.2 重装敌人：`3×1` 装甲横梁

重装敌人目前已经以 `3×1` 宽体形态存在，因此应正式定义为“横向封锁型”基底，而不是把 `heavyArmor` 视为普通随机词条。它的视觉核心不是更大的血条，而是横向三格的装甲梁、铆钉、厚边框和迟缓的移动节奏。它应该让玩家立即理解：这是一个会堵住横向通路、需要集中火力拆解的重型单位。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `3×1` |
| 专属词条 | `heavyArmor` |
| 可追加通用词条 | `shield`、`regen`、`berserk`，谨慎追加 `haste` |
| 轮廓语言 | 横向装甲板、三段铆接、中心厚甲核心 |
| 材质语言 | 暗铁、磨损边缘、低频金属高光 |
| 行为语义 | 高血量、慢移动、压缩可射击空间 |

重装敌人不建议与 `jump` 形成常规组合，因为“重装横梁”与“跨越阻挡”的身体语义相互冲突。如果确实需要做特殊变体，应另起基底，例如“攻城履带”，而不是让标准重装跳跃。

### 4.3 吞噬敌人：`2×2` 深渊胃囊

吞噬敌人建议从当前的普通词条表达升级为默认 `2×2` 基底。它的身体应像一个不稳定的胃囊或缺口圆环，底部有深色锯齿、内部有暗红旋涡和可见的吞噬腔。`devour` 不应再作为普通单格敌人的随机词条出现，而应成为 `maw` 基底的专属机制。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `2×2` |
| 专属词条 | `devour` |
| 可追加通用词条 | `shield`、`regen`、`clone` |
| 轮廓语言 | 缺口圆角矩形、内凹嘴部、底部锯齿阴影 |
| 材质语言 | 黑红有机质、腐蚀边缘、暗色吞噬旋涡 |
| 行为语义 | 吞噬邻近单位，继承生命与词条，形成倒计时压力 |

`devour + shield` 可以作为高阶吞噬变体，但其视觉必须让护盾表现为“覆盖在胃囊外层的半透明膜”，而不是普通单格敌人的六边形护盾框。这样玩家可以清楚地区分“带盾小怪”和“有护膜的吞噬核心”。

## 5. 3×3 范围内的新敌人类型设计

本节中的“3×3 范围”指普通战斗网格内的非 Boss 敌人最大占格不超过三列三行。原则上，`2×2` 及以上敌人不应大量同时出现，且每个大型基底都必须绑定一个专属词条，用于表达其独特职责。下表给出建议的尺寸矩阵。

| 尺寸 | 基底名称 | 专属词条 | 战术职责 | 默认出现阶段 | 设计状态 |
|---|---|---|---|---|---|
| `1×1` | 炼金残渣 | 无 | 通用载体与阵型填充 | R1+ | 既有基础 |
| `2×1` | 棱盾兽 | `deflectionWard` | 以小型偏折屏障克制反弹与穿透伤害 | R9+ | 新增建议 |
| `1×2` | 共振尖塔 | `echoRelay` | 额外触发一次周围敌人的词条效果，自身血量减半 | R10+ | 新增建议 |
| `2×2` | 深渊胃囊 | `devour` | 吞噬成长、倒计时压力 | R12+ | 既有机制升级 |
| `3×1` | 装甲横梁 | `heavyArmor` | 横向封锁、慢速推进 | R5+ | 既有实现固化 |
| `1×3` | 折光棱柱 | `prism` | 改变射线路径、反制激光 | R16+ | 新增建议 |
| `2×3` | 孵化巢 | `hive` | 周期生成弱小单位、占用纵深 | R18+ | 新增建议 |
| `3×2` | 攻城履带 | `siege` | 低频压迫、破坏阵型安全线 | R22+ | 新增建议 |
| `3×3` | 引力炉心 | `gravityWell` | 大型场控、牵引弹道与敌群 | R30+ | 新增建议 |

### 5.1 `2×1` 棱盾兽：`deflectionWard`

棱盾兽是横向短宽型敌人，但它不再承担主动切割或横向压迫职责，而是作为**反弹与穿透流派的局部校验点**。它的身体应像一块被炼金晶体包裹的低矮盾壳，左右两端有倾斜棱面，中部悬浮一层薄薄的偏折屏障。`deflectionWard` 词条表示它拥有等于自身最大生命值 `10%` 的屏障；该屏障只会阻挡反弹伤害与穿透伤害，不会阻挡普通直击伤害，也不会阻挡每回合结算的火焰持续伤害和毒属性伤害。如果屏障在一回合内没有被打破，则在下一回合开始时恢复至满屏障值。

这个机制的重点不是让棱盾兽成为单纯肉盾，而是让玩家理解“反弹/穿透路径需要先打穿偏折层”。因此视觉上不应继续使用刀刃、裂缝或攻击性楔形语言，而应改为晶盾、折角护片和薄膜式能量屏障。屏障存在时，棱盾兽上方可以绘制一条很短的青蓝色副条；屏障被击破后，副条消失并出现一帧碎裂晶片，直到下回合开始条件检查。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `2×1` |
| 专属词条 | `deflectionWard`（偏折屏障） |
| 屏障数值 | 最大生命值的 `10%` |
| 屏障拦截 | 只拦截反弹伤害与穿透伤害 |
| 屏障绕过 | 普通直击、每回合结算的火焰伤害、毒属性伤害 |
| 回合刷新 | 若上一回合结束时屏障未被打破，则本回合开始恢复至满屏障值 |
| 视觉关键词 | 低矮盾壳、倾斜棱面、青蓝薄膜、副屏障条、碎裂晶片 |
| 推荐通用词条 | `regen`、`shield`，谨慎追加 `haste` |
| 不推荐组合 | `berserk`，避免防御校验单位变成高压冲锋单位 |
| 克制引导 | 使用直击、火焰持续伤害或毒属性持续伤害绕过屏障；反弹和穿透流派需要先消耗屏障 |

### 5.2 `1×2` 共振尖塔：`echoRelay`

共振尖塔是纵向细高型敌人，适合作为后排或阵型核心。它不再直接提高周围敌人的词条强度，而是通过 `echoRelay` **额外触发一次周围敌人的词条效果**。这里的“周围敌人”建议按尖塔占格外缘一圈计算；对于当前 `1×2` 尺寸，可优先理解为与其外接矩形相邻的八方向格。被额外触发的词条应保持原词条自身的冷却、上限和合法性检查，避免 `clone`、`hive` 或治疗类效果在单回合内失控。

为了换取这种强力支援能力，共振尖塔的最大生命值应为同回合标准精英单位的 `50%`。因此它的视觉不应像厚重图腾，而应像一根脆弱但高能的空心共振柱：主体狭窄、外壳有裂纹，顶部晶核持续发出第二道回声波。玩家的预期应是“尽快点掉这个脆弱中继，否则周围敌人的词条会重复结算”。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `1×2` |
| 专属词条 | `echoRelay`（回响中继） |
| 血量修正 | 最大生命值为同回合标准精英单位的 `50%` |
| 触发规则 | 每回合额外触发一次周围敌人的词条效果，需遵守原词条自身冷却、上限与合法性检查 |
| 作用范围 | 默认按尖塔占格外缘一圈计算；实现时可用相邻八方向或基于外接矩形的邻接检测 |
| 视觉关键词 | 空心尖塔、裂纹晶核、双重环形波、细长能量柱、脆弱玻璃质感 |
| 推荐通用词条 | `shield`、`healer`、`regen`，但应限制叠加数量 |
| 不推荐组合 | `jump`，因为尖塔不应频繁位移；不建议与大型自增殖基底同场高密度出现 |
| 克制引导 | 优先集火低血量尖塔；`lightning` 可连锁清理护卫，`scatter` 可覆盖尖塔周边单位 |

### 5.3 `1×3` 折光棱柱：`prism`

折光棱柱是专门服务于射线路径玩法的纵向大型敌人。它不应简单复制 `shield` 的激光反射，而应提供更可读、更稳定的折射规则。`prism` 可以让激光或射线类攻击在命中后按固定角度偏转，或者把一次激光分成低伤害的两束折光。视觉上，它应保持高亮晶体切面，使用青蓝与白色高光，并在中心绘制纵向折射线。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `1×3` |
| 专属词条 | `prism`（折光） |
| 视觉关键词 | 长棱镜、透明切面、白色折射线、青蓝边缘光 |
| 推荐通用词条 | `shield`、`regen` |
| 不推荐组合 | `clone`，避免折射单位过量复制导致弹道不可读 |
| 克制引导 | `scatter` 绕过单点折射，`bounce` 利用侧面角度 |

### 5.4 `2×3` 孵化巢：`hive`

孵化巢是纵深型大型敌人，用于制造持续压力。它与 `clone` 的区别在于：`clone` 是自身复制的不稳定分裂，而 `hive` 是周期性生成低血量幼体。幼体应为 `1×1`，默认无词条或只携带非常弱的通用词条。视觉上，孵化巢应有多个半透明卵囊、纵向肉质隔膜和底部黏液阴影，强调“持续产出”而不是“瞬间爆发”。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `2×3` |
| 专属词条 | `hive`（孵化） |
| 视觉关键词 | 卵囊、半透明膜、黏液底边、内部幼体轮廓 |
| 推荐通用词条 | `regen`、`shield`、`healer` |
| 不推荐组合 | `devour`，避免大型成长机制叠加过重 |
| 克制引导 | `pyro` 持续压制，`laser` 集中烧穿核心 |

### 5.5 `3×2` 破阵履带：`siege`

破阵履带介于普通大型精英和 Boss 之间，适合作为章节后半段的高压精英。它占三列两行，视觉上应像横向履带车或炼金压路机。`siege` 的机制不再是额外回合推进，而是**冰冻免疫与阻挡推挤**：它无法被冰冻；当它执行移动且前方被其他敌人阻挡时，会尝试将阻挡链条一起向前推动一行。该敌人不应拥有 Boss 级血量和阶段机制，而是作为破坏玩家控场节奏、打乱前排站位并压缩战场空间的阵线推进器存在。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `3×2` |
| 专属词条 | `siege`（破阵） |
| 视觉关键词 | 双排履带、前置推铲、黄色警戒线、抗冻热管、推挤尘埃 |
| 推荐通用词条 | `heavyArmor` 不再作为词条叠加，而是通过装甲材质表现；可追加 `berserk` 或 `shield` |
| 不推荐组合 | `haste`，避免大体型高速推挤造成不公平压迫 |
| 克制引导 | `pierce` 穿透装甲节点；`cryo` 不再能冻结它，但仍可通过低温结算参与其他敌人的控场链路 |

### 5.6 `3×3` 引力炉心：`gravityWell`

引力炉心是 3×3 范围内的最大非 Boss 敌人，应该非常稀有，并且只在高阶回合或特殊导演阵型中出现。它的职责不是单纯肉盾，而是改变战场几何：`gravityWell` 可以轻微牵引附近敌人、影响弹道速度，或者让靠近它的投射物发生可预测的偏折。视觉上，它应拥有明显的中心黑核、三层环形结构和向内塌缩的网格线。

| 项目 | 规范 |
|---|---|
| 默认尺寸 | `3×3` |
| 专属词条 | `gravityWell`（引力井） |
| 视觉关键词 | 黑色核心、环形炉壁、向心网格、紫黑空间扭曲 |
| 推荐通用词条 | `shield`、`regen`，最多追加一个 |
| 不推荐组合 | `clone`、`devour`、`hive`，避免大型敌人自增殖或自成长失控 |
| 克制引导 | `laser` 稳定穿核，`pierce` 直击中心，`cryo` 降低引力脉冲频率 |

## 6. 新增专属词条规范

新增词条不应全部进入普通随机词条池。本文建议把它们定义为“**基底专属词条**”：只有当生成对应尺寸和基底时才会出现。这既能保持通用词条池的清晰，也能避免玩家在小怪身上看到过多不可预期机制。

| 词条 ID | 中文名 | 绑定基底 | 默认尺寸 | 行为概念 | 视觉锚点 |
|---|---|---|---|---|---|
| `deflectionWard` | 偏折屏障 | 棱盾兽 | `2×1` | 获得最大生命值 `10%` 的屏障；屏障只阻挡反弹与穿透伤害，若未被击破则每回合开始回满。 | 倾斜棱面、青蓝薄膜与短副屏障条。 |
| `echoRelay` | 回响中继 | 共振尖塔 | `1×2` | 额外触发一次周围敌人的词条效果；自身最大生命值减半。 | 空心尖塔、裂纹晶核与双重环形波。 |
| `prism` | 折光 | 折光棱柱 | `1×3` | 按固定规则折射或分束射线。 | 纵向棱镜切面与白色折射线。 |
| `hive` | 孵化 | 孵化巢 | `2×3` | 周期性生成低血量幼体。 | 卵囊、黏液和幼体剪影。 |
| `siege` | 破阵 | 破阵履带 | `3×2` | 无法被冰冻；移动被前方敌人阻挡时，将阻挡链条一起向前推一行。 | 履带、推铲、抗冻热管和警戒线。 |
| `gravityWell` | 引力井 | 引力炉心 | `3×3` | 牵引或偏折弹道，形成大型场控。 | 黑核、环形炉壁和向心网格。 |
| `siphon` | 汲能 | 汲能坩埚 | `2×2` | 吸收附近死亡或温度变化，转化为护盾或回血。 | 液面、导管和上升气泡。 |

其中 `siphon` 是可选补充基底，适合作为第二种 `2×2` 敌人。它与 `devour` 的区别在于，`devour` 直接吞掉友军并继承资源，表现为主动捕食；`siphon` 则吸收战场残留能量，表现为被动汲取。两者不能同时出现在同一敌人身上。

## 7. 视觉层叠规则：基底优先，词条后置

大型基底的视觉不应被通用词条覆盖。渲染时建议采用以下优先级：先绘制占格轮廓和基底材质，再绘制血量与温度反馈，然后绘制专属词条结构，最后绘制通用词条光环。这样可以确保 `2×2` 吞噬敌人即使带有 `shield`，玩家仍然首先看到“胃囊”和“吞噬腔”，而不是只看到一个大护盾框。

| 绘制顺序 | 内容 | 示例 |
|---|---|---|
| 1 | 基础占格阴影与碰撞轮廓 | `3×1` 横向阴影、`2×2` 圆形胃囊阴影 |
| 2 | 基底材质 | 装甲铆钉、卵囊、棱镜切面、黑核炉壁 |
| 3 | 血量、延迟血条与温度反馈 | 液体血条、过热裂纹、冰霜裂纹 |
| 4 | 专属词条结构 | 吞噬腔、折光线、孵化囊、引力环 |
| 5 | 通用词条特效 | 护盾网格、再生藤蔓、极速残影、治疗星芒 |
| 6 | Elite/Boss 边框与强调 | 紫晶核心、金色流光、Boss 深渊熔炉 |

对于 `2×2` 以上敌人，通用词条的视觉表现应按尺寸进行缩放，但不应简单等比放大。例如，`shield` 在 `1×1` 上可以是外框，在 `3×1` 重装上应表现为三段装甲板之间的能量桥，在 `3×3` 引力炉心上则应表现为环形护罩节点。

- `src/entities/enemy.js` 已新增 `_drawThreatTierBadge()`：Boss、精英和大型基底在左上角显示短标签（如“首领”“精英”“装甲”“吞噬”），用于第一眼识别威胁层级与基底职责。

## 8. 生成与难度曲线建议

大型基底敌人应进入导演系统，而不是直接进入普通 `spawn_generateAffixes()` 随机池。普通词条池仍负责制造精英小怪的变化，基底敌人则负责制造阵型主题和战术事件。这样可以保持关卡节奏可控，避免同一回合随机出现多个大型机制单位。

| 阶段 | 回合 | 可引入基底 | 设计意图 |
|---|---|---|---|
| 基础教学段 | R1-R5 | `1×1`、少量 `3×1 heavyArmor` | 教玩家识别宽体封锁与慢速单位。 |
| 持续压力段 | R6-R12 | `2×1 deflectionWard`、`1×2 echoRelay`、`2×2 devour` | 引入尺寸变化、防反弹/穿透校验点和低血量阵型中继。 |
| 群体控制段 | R13-R19 | `1×3 prism`、`2×3 hive` | 让玩家处理射线路径和持续产怪。 |
| 机制复合段 | R20-R26 | `3×2 siege` | 通过大型推进单位压缩空间。 |
| 进阶测试段以后 | R27+ | `3×3 gravityWell` | 引入稀有大型场控单位，形成局部 Boss 感。 |

生成数量上，`2×2` 敌人同屏建议不超过 2 个，`2×3` 与 `3×2` 同屏建议不超过 1 个，`3×3` 同屏只能出现 1 个，并且应暂停其他大型基底生成。大型基底可以携带一个通用词条作为变体，但不建议在同一敌人身上叠加两个以上通用词条。

## 9. 推荐落地顺序

第一步应先把现有 `heavyArmor` 与 `devour` 从“普通词条视觉”提升为“基底专属词条视觉”。其中 `heavyArmor` 已经接近完成，只需要补充正式的 `3×1` 视觉规范、碰撞边界和图鉴说明；`devour` 则应从单格词条升级为默认 `2×2` 深渊胃囊，并调整 `food_chain` 阵型中的吞噬核心尺寸。

第二步可以加入两个低风险新基底：`2×1 deflectionWard` 与 `1×2 echoRelay`。前者用于验证“局部屏障只影响特定伤害来源”的战斗可读性，后者用于验证“低血量中继重复触发周围词条”的阵型价值。第三步再引入 `1×3 prism` 与 `2×3 hive`，分别服务于弹道路径和持续产怪。最后，在性能预算和导演系统稳定后，再尝试 `3×2 siege` 与 `3×3 gravityWell`。

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | 固化 `3×1 heavyArmor` 与 `2×2 devour` | 直接回应当前已有机制，收益最高。 |
| P1 | 新增 `2×1 deflectionWard` 与 `1×2 echoRelay` | 低占格、低风险，适合验证屏障筛选与词条回响两类基底机制。 |
| P2 | 新增 `1×3 prism` 与 `2×3 hive` | 丰富弹道与持续压力玩法。 |
| P3 | 新增 `3×2 siege` 与 `3×3 gravityWell` | 高冲击大型单位，需要更谨慎的性能和关卡控制。 |
