# Echo Developer (Echo Alchemist V2 统一开发者)

本 Skill 是 Echo Alchemist V2 项目的统一开发入口。所有被分配代码修改任务的 Agent **必须**遵循本工作流，以确保代码质量、架构一致性以及活文档的同步更新。

## 标准工作流 (必须严格遵循)

1. **克隆/拉取仓库**
   - 目标仓库：`gdszyy/echo-alchemist-v2-1766564886`
   - 必须在执行任何修改前获取最新代码。

2. **读取全局规范与模块索引**
   - 读取仓库根目录下的 `AGENTS.md`。
   - 了解项目的全局开发规范和各子模块的职责划分。

3. **读取模块专属规范**
   - 根据当前任务涉及的模块，读取 `.cursor/rules/` 目录下对应的 `*.md` 规范文件。
   - 例如，修改 UI 相关代码时，必须读取 `.cursor/rules/ui_rules.md`（假设存在）。

4. **执行代码修改**
   - 遵循下文的 **智能编辑策略决策树** 进行代码修改。
   - 确保修改符合已读取的全局和模块规范。

5. **同步更新文档 (关键步骤)**
   - **在同一个 Commit 中**，必须同步更新对应模块的 `.cursor/rules/*.md` 或其他相关架构文档。
   - 确保“活文档”始终反映最新的代码状态。

6. **提交与保存交付物**
   - 提交 Git Commit。
   - 使用 `hub_repo.py save-result` 将修改后的代码文件和文档作为交付物保存到 Git 文档库。

## 智能编辑策略决策树

在修改代码时，请根据修改规模选择最合适的编辑策略：

- **微型修改 (< 20 行)**
  - **策略**：使用搜索替换 (Search & Replace) 或 `sed`。
  - **适用场景**：变量名重命名、简单的逻辑修复、单行配置修改。

- **中型修改 (20 - 200 行)**
  - **策略**：使用 Unified Diff 格式进行局部替换，或使用 `edits` 工具进行精准修改。
  - **适用场景**：函数重构、添加新方法、局部逻辑重写。

- **大型修改 (> 200 行)**
  - **策略**：全文件重写 (Full File Rewrite)。
  - **适用场景**：模块整体重构、引入大型新特性。
  - **注意**：需极其谨慎，确保不会意外删除其他不相关的逻辑。

- **脚本化修改 (跨文件/结构性)**
  - **策略**：编写 Python 脚本或复杂的 `sed`/`awk` 脚本进行批量处理。
  - **适用场景**：全局 API 签名变更、大规模文件重命名或移动。

## 禁止行为清单

为了维护项目的健康发展，以下行为被**严格禁止**：

1. **禁止全量交付超过 500 行的文件**：对于超大文件，必须进行模块化拆分，或者仅提交 Diff/局部修改。
2. **禁止跳过文档更新步骤**：代码修改必须伴随对应的文档（尤其是 `.cursor/rules/` 下的规范）更新。
3. **禁止在业务模块中直接操作 DOM**：Echo Alchemist V2 是基于 Canvas 的游戏，所有渲染逻辑必须通过 Canvas API 或专门的渲染系统进行，严禁在核心逻辑中穿插 DOM 操作。
4. **禁止使用未授权的第三方库**：所有新依赖的引入必须经过协调者或架构师的批准。
5. **禁止在主分支直接开发**：所有任务必须在对应的特性/修复分支上进行。
