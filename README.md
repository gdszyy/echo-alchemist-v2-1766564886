# Echo Alchemist (回聲煉金師)

> 本项目是一个基于 HTML5 Canvas 和 JavaScript 开发的**回合制 Roguelike 打砖块游戏**。玩家需要在不同的阶段中做出策略选择、通过弹珠收集属性，并利用构建出的弹药队列抵御不断变强的敌人。

## 1. 游戏主流程 (Game Flow)

游戏的核心体验并非即时动作，而是围绕三个主要阶段进行的策略循环。详细流程可参考 [游戏流程文档](docs/architecture/game_flow.md)。

*   **命运抉择 (Selection Phase)**：在每轮开始前，玩家需要从随机生成的卡牌中选择初始属性或遗物，奠定本回合的构建基础。
*   **研磨阶段 (Gathering Phase)**：核心的“打砖块”玩法。玩家发射弹珠碰撞钉板（Pachinko），收集或变异各种属性，从而填充下一阶段使用的弹药队列。钉板上还可能出现特殊槽位（如连射、分裂、命运轮盘等），提供额外增益。
*   **战斗阶段 (Combat Phase)**：Roguelike 战斗环节。玩家使用在研磨阶段收集到的弹药队列，依次向敌人开火。战斗采用回合制推进，敌人拥有血量和各种词缀，玩家需要利用属性克制与连击机制清空敌人。

在局外，玩家还可以通过**炼金工坊 (Workshop)** 使用局内收集的“能量精粹”进行永久升级，例如提升初始属性权重、加固防线、增加遗物选择数量等。

## 2. 核心机制详解

### 2.1 属性与进化系统
游戏内包含丰富的属性流派，弹珠与钉子的碰撞会触发收集、升级或变异。详细的属性设计和数值平衡可在 [`src/config.js`](src/config.js) 中查看。

*   **物理系**：如 `bounce`（反弹）、`pierce`（穿透）、`scatter`（散射）。
*   **元素系**：如 `pyro`（火焰，造成持续燃烧与过热爆炸）、`cryo`（冰霜，造成减速与冻结）、`lightning`（闪电，触发连锁伤害）。
*   **高级/特殊系**：如 `wind`（风，生成风暴法阵）、`laser`（激光，高能穿透）、`flying_sword`（飞剑）、`matryoshka`（套娃）等。

### 2.2 敌人与词缀系统
随着回合推进，敌人的血量会呈指数级增长，并可能携带各种棘手的词缀。
常见的敌人词缀包括：护盾（减伤）、极速（多次行动）、再生（回血）、增殖（受击或回合开始时分裂）、狂暴、治愈、吞噬、跳跃等。

玩家可以在游戏内的**真理之书 (Truth Book)** 中查看所有敌人词缀和属性流派的详细图鉴与实时动画演示。相关数据定义在 [`src/systems.js`](src/systems.js) 中。

### 2.3 符文词条系统 (Rune System)
符文系统是游戏局内的核心策略维度之一，结合了“智能掉落”与“网格拼图”玩法。详细设计请参阅 [符文系统重构设计方案](docs/rune_system_redesign.md)。

*   **智能掉落**：敌人的符文掉落并非纯随机。系统会分析玩家近几回合的伤害构成（如火焰伤害占比高），并结合**套路克制关系**（如火焰克制护盾/再生），动态提高相关符文的掉落权重。具体算法见 [`src/loot_system.js`](src/loot_system.js)。
*   **双重增益**：
    *   **基础加成**：将符文放入 3x3 的发射器网格中，即可为所有弹药提供对应的属性层数加成（如烈焰符文提供 `pyro` 层数）。
    *   **组合词条**：当网格中的符文排列满足特定形状（如直线、对角线）时，可激活强力的“符文之语”（如“烈焰之语”、“雷暴之语”），提供额外的机制质变。
*   **合成与重铸**：多余的符文可以进行同系合成（提升等级与基础加成）或跨系重铸（获取新符文）。符文与词条的完整数据字典见 [`src/rune_config.js`](src/rune_config.js)。

### 2.4 试炼场 (Training Ground)
为了方便玩家测试不同属性组合的强度，游戏内置了独立的试炼场模式。玩家可以自由配置子弹的各项属性层数，生成带有特定词缀的敌人，并通过伤害统计看板（Damage Analytics）直观分析各属性的伤害占比。

## 3. 项目架构与源码导航

本项目已全面迁移至模块化的原生 JavaScript 架构。核心逻辑解耦为多个子系统：

| 模块文件 | 核心职责 |
| :--- | :--- |
| [`src/core.js`](src/core.js) | 游戏引擎核心，管理全局状态、主循环和音频初始化。 |
| [`src/game_system.js`](src/game_system.js) | 阶段分发、存档读写、游戏重置与输入管理。 |
| [`src/game_phase.js`](src/game_phase.js) | 命运抉择、研磨、战斗等各个阶段的具体逻辑与转场。 |
| [`src/combat_system.js`](src/combat_system.js) | 战斗结算、伤害统计、动态难度调整（DDA）评估。 |
| [`src/config.js`](src/config.js) | 全局常量、属性字典、遗物（`RELIC_DB`）、技能（`SKILL_DB`）与商店配置。 |
| [`src/entities.js`](src/entities.js) | 实体定义（如弹珠、鑉子、敌人、特效粒子及特殊槽位）。 |
| [`src/plinko_physics.js`](src/plinko_physics.js) | **鑉盘物理引擎与概率分析模块**。基于 Galton Board 理论，提供增强版碰撞物理（角动量、速度依赖弹性、表面摩擦、Magnus 效应）、二项分布落点预测和布局专属物理参数配置。 |

更多技术细节和历史设计文档，请查阅 `docs/` 目录下的相关文件。

> **注**：之前的 Godot 4.x 迁移尝试已归档至 `docs/archive/godot_migration/`，当前主干专注于 HTML5 Canvas 版本。

## 4. 架构改造与 AI 协作流升级计划 (Ongoing)

目前项目正在进行大规模的架构改造，旨在降低 AI 辅助开发时的 Token 消耗，彻底消除巨型 Mixin 模式，并建立基于 Git 的活文档（Living Documentation）知识库。

改造工程分为三个主要阶段：
1. **基础设施与知识库搭建**：建立 `.cursor/rules/` 目录和 `AGENTS.md` 索引，规范 AI 调度流程。
2. **核心模块物理拆分**：将 `entities.js`、`combat_system.js` 等巨型文件拆分为更小粒度的文件。
3. **架构解耦与通信重构**：完善 `EventBus` 机制，彻底分离 UI 层与业务逻辑。
